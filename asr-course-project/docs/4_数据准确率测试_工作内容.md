## 0. 一句话说明我负责什么

定义并实现 **CER（Character Error Rate，字错率）** 的计算与评估流程：用 Levenshtein 编辑距离统计替换/删除/插入，在训练集和 TIMIT 官方 TEST 上跑批量推理，输出可复现的 CER 结果文件，并对错误构成做归因分析。

我的交付物是**一组带数字的评估结论**，不是“感觉识别得不错”。

## 2. 指标定义：CER 到底怎么算

### 2.1 公式

```
CER = (S + D + I) / N
```

- `S`：替换数（substitutions），参考字符被识别成别的字符；
- `D`：删除数（deletions），参考字符没被识别出来；
- `I`：插入数（insertions），识别结果多出了参考中没有的字符；
- `N`：参考文本字符总数。

`S + D + I` 就是参考文本与识别文本的**最小编辑距离**（Levenshtein distance）。

### 2.2 语料级 CER（本项目采用）

```
语料级 CER = Σ(S + D + I) / ΣN
```

**不是**对每条样本的 CER 求平均。原因：短句和长句的权重应当按字符数计，逐条平均会让短句权重失真。实现见 `cer.py` 第 158–209 行。

### 2.3 一个手算例子

参考：`abcdef`，识别：`abcdf`

- 删除一个 `e`：`D=1`，`S=0`，`I=0`；
- `CER = 1 / 6 = 16.67%`。

### 2.4 空格与标点的实际处理（必须讲清楚）

`evaluate_model()` 调用 `compute_cer_corpus(refs, hyps)` 时**没有传 `remove_space=True`**（`cer.py` 第 299 行），所以：

- **空格参与 CER**：英文词边界是字符之一；
- `_normalize_text()` 会做 NFKC 规范化，并删除常见标点（`cer.py` 第 215–230 行），其中**包括撇号**；
- 参考文本和识别文本走**同一套规范化**，所以比较是同口径的；
- 如果想让空格不参与，可在 `single` / `batch` 模式加 `--remove_space`；`evaluate_model` 当前不暴露这个开关。

> 汇报时不要笼统说“CER 不含空格”。准确说法是：**批量端到端评估默认包含空格，但撇号等标点会被规范化删除；ref 和 hyp 同规则。**

## 3. 代码是怎么构建的（`cer.py`）

### 3.1 编辑距离与 S/D/I 回溯（第 23–84 行）

```python
# dp[i][j] = ref 前 i 个字符与 hyp 前 j 个字符的编辑距离
dp[i][j] = min(dp[i-1][j] + 1,      # 删除
               dp[i][j-1] + 1,      # 插入
               dp[i-1][j-1] + 1)    # 替换
```

- **第 44–49 行**：初始化边界；
- **第 51–60 行**：填 DP 表；字符相等时直接继承左上角，否则取三种操作的最小值；
- **第 62–84 行**：从右下角回溯，按“相等 → 替换 → 删除 → 插入”的优先级统计三类错误；
- **第 83 行**：返回 `(distance, substitutions, deletions, insertions)`。

回溯的意义：编辑距离只给一个总数，回溯才能知道错误**是替换多、删除多还是插入多**，这是后面归因分析的基础。

### 3.2 单条 CER（第 87–121 行）

```python
if remove_space:
    ref = ref.replace(" ", ""); hyp = hyp.replace(" ", "")
if normalize:
    ref = _normalize_text(ref); hyp = _normalize_text(hyp)
distance, s, d, i = levenshtein_distance(ref, hyp)
return distance / len(ref)
```

- `remove_space`：是否去掉空格；
- `normalize`：是否做 NFKC + 去标点；
- 空参考：若 hyp 非空返回 `len(hyp)`，否则 0（第 116–117 行）。

### 3.3 单条详细信息（第 124–155 行）

返回一个 dict：

```python
{"cer", "distance", "substitutions", "deletions", "insertions",
 "ref_len", "hyp_len", "ref", "hyp"}
```

用于逐条排查：哪句话错、错在哪个字。

### 3.4 语料级汇总（第 158–209 行）

```python
for ref, hyp in zip(refs, hyps):
    detail = compute_cer_detailed(ref, hyp, remove_space)
    total_distance += detail["distance"]
    total_substitutions += detail["substitutions"]
    total_deletions += detail["deletions"]
    total_insertions += detail["insertions"]
    total_ref_len += detail["ref_len"]

cer = total_distance / total_ref_len
```

返回字段（第 197–209 行）：

| 字段 | 含义 |
|---|---|
| `cer` | 语料级字错率 |
| `total_distance` | 总错误数 |
| `total_substitutions` / `substitution_rate` | 替换数 / 替换率 |
| `total_deletions` / `deletion_rate` | 删除数 / 删除率 |
| `total_insertions` / `insertion_rate` | 插入数 / 插入率 |
| `total_ref_len` | 参考总字符数 |
| `per_sample_cers` | 每条样本的 CER（保存时被过滤掉） |
| `num_samples` | 样本数 |

**关键**：`cer` 用的是 `total_distance / total_ref_len`，不是 `mean(per_sample_cers)`。

### 3.5 文本规范化（第 215–230 行）

```python
text = unicodedata.normalize("NFKC", text)
text = re.sub(r"[，。！？、；：""''（）《》【】\-,.!?:;'\"()\[\]{}]", "", text)
text = text.strip()
```

- 统一全角/半角；
- 删除中英文常见标点（包括撇号 `'`）；
- 只去掉首尾空白，**内部空格保留**。

### 3.6 端到端评估 `evaluate_model`（第 236–319 行）

执行顺序：

| 步骤 | 行号 | 动作 |
|---|---|---|
| 1 | 261–266 | 加载 `SpeechRecognizer(model_path, beam_width)` |
| 2 | 269–270 | `SpeechDataset(test_dir, vocab)` 读测试集清单 |
| 3 | 275–296 | 逐条：读 wav → 转单声道 → 重采样 → `recognize()` |
| 4 | 295–296 | 收集 `refs` / `hyps` |
| 5 | 299 | `compute_cer_corpus(refs, hyps)` |
| 6 | 301–310 | 打印总样本、总参考字数、总错误、S/D/I、CER |
| 7 | 312–317 | 结果写 JSON（过滤掉 `per_sample_cers`） |

需要注意：`evaluate_model` 重新用 `soundfile` 读每条音频（第 281–291 行），并没有用第 1 部分的特征缓存；但特征提取仍走 `SpeechRecognizer.extract_features`，所以特征定义和归一化是一致的。

### 3.7 错误可视化 `analyze_errors`（第 325–353 行）

用 `difflib.Differ` 对参考和识别做逐字对比，输出：

```text
参考: ...
识别: ...
编辑距离: N (替换:x, 删除:y, 插入:z)
逐字对比: ...
```

适合现场挑一条错例展示。

### 3.8 命令行入口（第 359–436 行）

三种模式：

| 模式 | 行号 | 命令 | 用途 |
|---|---|---|---|
| `single` | 387–395 | `python cer.py single --ref "..." --hyp "..." --detailed` | 单条手算/演示 |
| `batch` | 397–411 | `python cer.py batch --input pairs.json --output result.json` | 已有 ref/hyp 对，批量算 |
| `eval` | 413–420 | `python cer.py eval --model ... --test_dir ... --output ...` | 端到端：推理 + CER |

## 4. 实验结果（本部分的核心产出）

### 4.1 训练集自评：`evals/eval_result.json`

| 字段 | 数值 |
|---|---|
| 样本数 | 4618 |
| 参考总字符 | 217,011 |
| 总错误 | **7** |
| 替换 S | 0 |
| 删除 D | **7** |
| 插入 I | 0 |
| **CER** | **3.225642939758814e-05 = 0.0032%** |

解读：模型在训练集上几乎完全复现标签，只有 7 个字符被漏掉。说明“特征 → 模型 → CTC → greedy → CER”整条链路在见过的数据上是通的。

> 注意：这是**训练集自评**，不是泛化指标。4618 条既是训练集又是评估集，CER 接近 0 只能说明拟合充分。

### 4.2 TIMIT 官方 TEST：`evals/eval_test.json`

| 字段 | 数值 | 占比 |
|---|---|---|
| 样本数 | **1680** | — |
| 参考总字符 | **78,758** | — |
| 总错误 | **15,721** | — |
| 替换 S | **8,410** | **10.68%** |
| 删除 D | **5,197** | **6.60%** |
| 插入 I | **2,114** | **2.68%** |
| **CER** | **0.19961146804134183 = 19.96%** | 19.96% |

三项错误率相加正好等于 19.96%，说明汇总口径自洽。

### 4.3 训练过程对比：epoch 50 → 100

| 结果文件 | 模型 | 测试集 CER |
|---|---|---|
| `evals/eval_e50.json` | epoch 50 | **21.16%** |
| `evals/eval_e75.json` | epoch 75 | **20.40%** |
| `evals/eval_e85.json` | epoch 85 | **20.02%** |
| `evals/eval_e95.json` | epoch 95 | **19.99%** |
| `evals/eval_test.json` | best（约 epoch 100） | **19.96%** |

趋势：**21.16% → 20.40% → 20.02% → 19.99% → 19.96%**，后 50 个 epoch 只改善约 1.2 个百分点，已经进入平台区。

### 4.4 训练 loss 对照（`checkpoints/history.json`）

| 指标 | epoch 1 | epoch 100 |
|---|---|---|
| train_loss | 6.638 | 0.000543 |
| val_loss | 2.979 | 0.00004195 |

训练 loss 持续下降、验证 loss 也下降，但**测试集 CER 停在 19.96%**。这说明优化目标（CTC loss）和最终指标（CER）之间仍有差距，且模型对训练集分布过拟合。

### 4.5 结果解读（汇报重点）

**（1）训练集 vs 测试集的巨大差距**

| 评估集 | CER |
|---|---|
| 训练集 4618 条（同源自评） | **0.0032%** |
| TIMIT TEST 1680 条（未见说话人） | **19.96%** |

差距约 **6000 倍**。原因不是“评估代码写错”，而是：

- 训练集自评用的是模型见过的 4618 条，4618 条只来自 462 个说话人；
- TEST 是 168 个**未见说话人**，口音、语速、录音条件都不同；
- 模型 29.98M 参数、训练 100 epoch，容量足以“记住”训练集。

**（2）错误构成不同**

| 评估集 | 替换 | 删除 | 插入 | 主要问题 |
|---|---|---|---|---|
| 训练集 | 0 | **7（100%）** | 0 | 极少数漏字 |
| TEST | **8,410（53.5%）** | 5,197（33.1%） | 2,114（13.4%） | 替换为主，说明声学区分度不足 |

- **替换多**：模型听到了音，但分不清是哪个字母/词，常见于口音、连读、相近发音；
- **删除多**：模型偏保守，一些字符被 blank 覆盖；
- **插入多**：模型多输出了字符，常见于拖音、噪声段。

**（3）为什么 CER 不是 0**

- 字符级 CTC 没有语言模型约束，条件独立假设下学不到词间语言规律；
- 词表只有 29 类，没有大小写、标点，参考文本和识别文本都做了清洗，但仍存在同音/近音混淆；
- 双向 LSTM 需要整句输入，句末信息会影响前向，但不是流式场景；
- 训练数据只有 4618 条、236.5 分钟，对声学建模仍然偏少。

**（4）结论**

- 链路正确性：**训练集 0.0032%** 证明“数据处理 → 模型 → CTC → 推理 → CER”全部打通；
- 泛化能力：**TEST 19.96%** 是当前模型的真实水平，约 80% 字符正确；
- 评估结论可信：S/D/I 三项相加等于总 CER，且 epoch 50→100 的曲线单调改善，符合训练 loss 的趋势。

## 7. 常见坑与处理

| 现象 | 根因 | 处理 |
|---|---|---|
| CER 与手算不一致 | 逐条平均 vs 语料级累计 | 必须用 `Σ(S+D+I)/ΣN`，不能用 `mean(per_sample_cers)` |
| 空格到底算不算 | `evaluate_model` 默认 `remove_space=False` | 汇报时明确“默认含空格”；需要去空格用 `--remove_space` |
| 撇号消失了 | `_normalize_text` 删除标点（含 `'`） | ref/hyp 同规则，指标仍公平；不要只对单边清洗 |
| CER 100%（全删除） | 模型 blank 塌缩或词表为空 | 查 checkpoint 是否 29 类、训练是否 warmup；用单条 `analyze_errors` 看 |
| 评估结果和上次不一致 | 换了 checkpoint / beam_width / 数据清单 | 固定 `--beam_width 1`、固定 `test_dir`、记录 checkpoint 文件名 |
| JSON 里没有逐条 CER | 保存时过滤 `per_sample_cers` | 需要逐条分析就在 Python 里直接调 `compute_cer_corpus()` 拿完整 dict |
| 测试集 CER 与训练集差距过大 | 同源自评 vs 未见说话人 | 这是泛化问题，不是评估 bug；报告里要分开写 |
| 评估很慢 | 逐条读 wav + 前向，未用特征缓存 | 1680 条可接受；需要更快可先缓存测试集特征 |
| `torch.load` 报 `No module named 'dataset'` | checkpoint 含 `Vocabulary` 对象 | 在项目根执行 |
