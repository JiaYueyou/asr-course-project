# 分析文档：5 层 BiLSTM + CTC 语音识别（TIMIT 50 条自研复现）

> 本文档是**编码前的需求分析**（复现规划中的里程碑 M1）。
> 所有设计决策基于已就绪的真实数据（`data/proc/`，50 条 TIMIT 英文句子），
> 代码尚未编写；本文档确认后才进入 M3 实现。
>
> 定位声明：本项目的目标是**算法链路复现**——在能完全学下来的小数据上，
> 验证"特征 → 词表 → BiLSTM → CTC → 解码 → CER"每一环都实现正确。
> 不对标大数据集指标，不追求 SOTA。

---

## 0. 任务定义与数据事实

**任务**：给定 16 kHz 单声道英文语音，输出对应的字符序列（含词间空格）。

**已就绪的数据事实**（`prepare_timit.py` 产出，均已实测）：

| 项目 | 数值 |
|---|---|
| 条数 / 说话人 | 50 条 / 10 人（每人 5 条，TIMIT TRAIN 划分） |
| 音频总量 | 2.7 分钟，时长 2.07–5.57 s，均值 3.22 s |
| 帧数 T（100 fps） | 205 – 555，均值 320 |
| 字符数 L（含空格） | 27 – 78，均值 49 |
| T/L 比 | 最小 4.7（CTC 约束 T≥2L+1 的 2 倍以上余量） |
| 词表 | 29 类 = blank(0) + 26 字母 + 空格 + 撇号 |
| 音频格式 | RIFF PCM16 wav，`audio/` + `transcription.txt`（与 asr 格式一致） |

**数据规模决定了设计基调**：2.7 分钟语音 ≈ 1.6 万帧，50 条固定数据可以**全部常驻内存**，
训练目标是"学会这 50 条"（过拟合式验证），因此所有为大数据设计的机制
（分桶、多进程、学习率调度、混合精度）在本项目中**刻意省略**，省略理由在正文各节给出。

## 1. 系统需要哪些部分（模块清单与数据流）

### 1.1 数据流

```
wav (16k, PCM16)
  │  extract_log_mel
  ▼
log-mel 特征 [T, 80]          ← 不归一化的原始特征
  │  apply_cvn(feat, mean, std)   ← 全局 CMVN，统计量来自训练集且存进 checkpoint
  ▼
归一化特征 [T, 80]
  │  BiLSTMCTC.forward
  ▼
log_probs [T, B, 29]          ← log_softmax，可直接喂 CTCLoss
  │                          │
  ▼ 训练                     ▼ 推理
nn.CTCLoss                    greedy 逐帧 argmax → 合并重复 → 去 blank
  │                          │
  ▼                          ▼
loss 标量                    字符串
  │                          │
  └──────── eval.py ─────────┘
             │
             ▼
        CER + S/D/I 分析
```

### 1.2 模块清单（自研，不搬运 asr 代码）

| 文件 | 职责 | 关键接口 |
|---|---|---|
| `src/features.py` | log-mel 提取、CMVN 统计与应用 | `extract_log_mel(audio) -> [T,80]`；`compute_cvn(list) -> (mean,std)`；`apply_cvn(f, m, s)` |
| `src/vocab.py` | 词表加载/编码/解码 | `load_vocab(path)`；`encode(text) -> list[int]`；`decode(ids) -> str` |
| `src/dataset.py` | manifest 读取、特征缓存、padding 组批 | `TimitDataset(manifest_dir, vocab, cmvn)`；`collate_fn` |
| `src/model.py` | 5 层 BiLSTM-CTC 网络 | `BiLSTMCTC(input_dim, hidden, layers, num_classes, dropout)`；`forward(feats, lengths) -> log_probs[T,B,C]` |
| `src/train.py` | 训练循环、checkpoint 读写 | `python src/train.py --data data/proc --epochs 200` |
| `src/decode.py` | greedy 解码（beam 可选） | `greedy(log_probs, lengths) -> list[str]` |
| `src/eval.py` | CER 计算（编辑距离 + S/D/I 回溯） | `cer(ref, hyp) -> (S,D,I)`；`corpus_cer(pairs) -> float` |

### 1.3 与 asr 仓库的关系

- **格式契约一致**：manifest（`文件名 文本`）、`audio/` 目录布局相同，可用 asr 的
  `SpeechDataset` 读取我们的数据做交叉验证；
- **代码独立**：所有模块按本文档自行编写；asr 只作行为参照
  （特征参数、CER 定义），不复制其实现；
- **工具借用**：`eval.py` 的 CER 结果可与 asr 的 `cer.py` 交叉对数验证正确性
  （借验证功能，不借实现）。

## 2. 词表与文本表示

### 2.1 已定的词表（`data/proc/vocab.json`）

- **29 类**：`idx 0 = <blank>`，其余 28 类 = 26 个小写字母 + 空格 + 撇号，按字符排序；
- **为什么含空格**：英文词边界是语言信息。CTC 建模空格后，解码输出可读、
  词间停顿有显式符号，也为后续（可选）WER 评估铺路；
- **为什么无 `<unk>`**：50 条固定文本构成封闭集合，训练/评估不会出现集外字符。
  若未来换数据，策略是"集外字符在清洗阶段丢弃"并在 manifest 生成时记录，不引入 UNK 类
  （UNK 在 CTC 中没有合理对齐语义，还会污染 loss）；
- **blank 固定为 0**：`nn.CTCLoss(blank=0)`，与词表文件中的 `blank_id` 对应，
  编码时文本字符索引全部 +1（跳过 blank 槽位）。

### 2.2 文本清洗规则（已在数据准备阶段执行）

NFKC 规范化 → 小写 → 仅保留 `a-z` 与词内撇号 → 空格分词重组。
词表文件 `meta.text_normalization` 字段记录了该规则，训练/评估使用同一份 manifest，
**不存在二次清洗**，从源头消除文本不一致。

### 2.3 编解码往返约定

- `encode("abc") -> [idx_a, idx_b, idx_c]`（不含 blank）；
- `decode` 只做"索引 → 字符"映射，**不做去重/去 blank**——那是解码阶段
  （`decode.py`）的职责，两者分离便于对 CTC 输出分布做中间检查；
- 单元验收：50 条文本 `decode(encode(t)) == t` 全部成立。

## 3. 网络如何搭建（`src/model.py`）

### 3.1 结构与逐层形状

忠实复现 asr 的 DeepSpeech2 骨干（纯 FC 投影 + 5 层 BiLSTM，无卷积、无下采样、无 Norm），
仅按数据规模缩小隐层宽度：

| 层 | 配置 | 输出形状 |
|---|---|---|
| `input_fc` | Linear(80→128) + ReLU + Dropout(0.3) | `[B, T, 128]` |
| `lstm` | 5 层、hidden 128、**双向**、batch_first、层间 dropout 0.3 | `[B, T, 256]` |
| `output_fc` | Linear(256→128) + ReLU + Dropout(0.3) + Linear(128→29) | `[B, T, 29]` |
| 归一化 | `log_softmax(dim=-1)` | `[B, T, 29]` |

### 3.2 参数量核算（hidden=128、5 层、C=29）

| 部件 | 计算 | 参数量 |
|---|---|---|
| `input_fc` | 80×128+128 | 10,368 |
| BiLSTM 第 1 层（输入 128） | 2 方向 × (4·128·128 + 4·128·128 + 2·4·128) | 264,192 |
| BiLSTM 第 2–5 层（输入 256=2×128） | 每层 2 × (4·256·128 + 4·128·128 + 1,024) = 395,264 | 1,581,056 |
| `output_fc` | 256×128+128 + 128×29+29 | 36,637 |
| **合计** | | **≈ 1.89 M** |

对比原仓库 hidden=512 时约 22 M：50 条数据（≈1.6 万帧）配 1.89 M 参数，
记忆容量仍有大量冗余——这正是过拟合式验证想要的（模型必然能学会，
问题只剩"实现是否正确"）。

### 3.3 变长序列处理

- batch 内 padding 到最大 T，`lengths` 张量**保留在 CPU**（`pack_padded_sequence` 的要求）；
- `pack_padded_sequence(..., enforce_sorted=False)` → LSTM → `pad_packed_sequence`
  打包跳过 padding 帧：双向 LSTM 的反向传播会从序列末尾开始，padding 若不打包
  会污染反向方向的起点；
- **0 长度禁止**：`pack` 会在 0 长度样本上报错。数据侧已在准备阶段过滤
  （最短 2.07 s → T=205，全部远大于 0）；
- 推理时同样走打包路径（哪怕 batch=1），保证训练/推理走**同一条前向代码**。

### 3.4 初始化

- 线性层与 LSTM 权重：Xavier uniform（与原仓库一致）；
- LSTM 遗忘门偏置初始化为 1.0：让早期记忆通路 `∂c_t/∂c_{t-1} ≈ f_t ≈ 1`，
  小数据上收敛更快（设计增强项，asr 未做）。

### 3.5 为什么保留 5 层而不是缩到 3 层

结构保真优先：本复现的标题就是"5 层 BiLSTM + CTC"，层数是算法身份的一部分。
缩小 hidden（512→128）只改变容量、不改变结构，是允许的规模适配；
去掉两层则成了另一个模型。

## 4. 损失函数：为什么选 CTC

### 4.1 问题定义

输入帧序列 T 帧、标签 L 个字符，**T ≫ L**（本数据 T/L ≥ 4.7），且不知道第几个
字符对应第几帧（对齐未知）。要让"帧级输出"能算 loss，只有三条路：

| 方案 | 是否需要帧级对齐标注 | 是否单调假设 | 结论 |
|---|---|---|---|
| 强对齐（HMM/GMM 预对齐） | 需要（TIMIT 有 PHN 标注可做，但那是另一个工程） | 是 | 排除：引入外部对齐器，违背端到端复现目标 |
| Attention（软对齐） | 不需要 | 否 | 排除：换了算法本体，且小数据上 attention 极易过拟合 |
| **CTC（路径边缘化）** | **不需要** | 是 | **选定** |

TIMIT 虽然自带 `.PHN` 音素对齐，但用它就变成了"监督对齐 + 分类"任务，
失去"端到端从无对齐文本学习"这个复现主题。

### 4.2 CTC 要点（实现时必须处理对的细节）

- **路径**：帧级输出序列 π 经"合并连续重复 + 删 blank"映射到标签 l；
  blank 让重复字符（如 `aa`）可区分；
- **目标**：`P(l|x) = Σ_{π∈B⁻¹(l)} Π_t y_{π_t}^t`，取负对数；
  前向 DP 在 `O(T·L)` 内完成，本数据 T=555、L=78 时约 4.3 万格，
  PyTorch 内置 CUDA 实现，无性能问题；
- **长度约束** `T ≥ 2L+1`：数据侧已验证 50/50 通过（最小 T/L=4.7）；
  训练中仍设 `zero_infinity=True` 兜底，防止个别 batch 被 inf 污染。

### 4.3 `nn.CTCLoss` 接口契约（自己实现时最容易错的四处）

1. 输入形状是 **[T, B, C]**（时间优先），模型输出 [B,T,C] 后需 `transpose(0,1)`；
   我们让 `model.forward` 直接返回 [T,B,C]，把转置收进模型内，调用方不再关心；
2. `targets` 支持 2D 拼接式 `[ΣL]`（int32/int64 一维拼接）或 padded 2D；
   我们用**一维拼接 + `target_lengths`**，没有 padding 列，天然符合要求；
3. `input_lengths` 是**帧数**（padding 前），不是 padded 后的最大 T；
4. `reduction='mean'` 是按 target 长度加权的平均，不是 batch 平均——
   比较不同 epoch 的 loss 时无需自己再归一，但**不能**用它直接换算"每字符 loss"。

### 4.4 CTC 的三个性质（决定后续设计）

1. **条件独立**：给定输入，各帧输出独立 → CTC 学不到字符间语言约束。
   50 条小数据上这不是瓶颈（记忆即可），但意味着 beam+LM 类增强收益有限，
   属可选增强；
2. **尖峰性**：最优解把每个字符压到一两帧、其余帧输出 blank。
   预期训练后期解码输出里 blank 占 >90%，**greedy 输出大量空帧是正常现象**；
3. **早期 loss 平坦**：模型先要学会"全输出 blank"（loss ≈ ln 29 ≈ 3.4 一带），
   再逐步学会把字符概率从 blank 里"挤"出来——训练初期 loss 长时间小幅波动
   然后突然下降是正常轨迹，不是 bug。

## 5. 特征前端与归一化（`src/features.py`）

### 5.1 log-mel 参数（与 asr 对齐，便于结果对照）

| 参数 | 值 | 理由 |
|---|---|---|
| win_length | 400 采样点（25 ms） | 语音短时平稳性的经典窗长 |
| hop_length | 160 采样点（10 ms） | 100 fps，与 T≥2L+1 校验一致 |
| n_fft | 512 | 覆盖 400 点窗，频率分辨率 31.25 Hz |
| n_mels | 80 | Kaldi/DeepSpeech 惯例 |
| f_min / f_max | 80 / 7600 Hz | 去直流低频嗡声；略低于奈奎斯特 8 kHz |
| 压缩 | log10(max(power, 1e-10)) | 语音动态范围 ~60 dB，必须取对数 |

用 librosa（环境已含）实现；不写无 librosa 时的兜底路径——原仓库兜底路径
在短音频下会产生负帧数导致崩溃，本项目环境可控，直接依赖 librosa 即可。

### 5.2 归一化：全局 CMVN，训练/推理同源（设计约束第 2 坑的正面规避）

原仓库训练不归一化、推理逐条归一化，输入分布不一致，是它最致命的 bug。
本项目的设计：

1. 启动训练时先对 **50 条全部特征**（约 1.6 万帧 × 80 维）统计逐维 mean/std；
2. 训练、验证、推理**一律**用这组统计量 `apply_cvn`；
3. `mean`/`std` 与特征参数一起**存进 checkpoint**（见 §9），
   推理端只从 checkpoint 读取，不存在"再统计一次"的可能；
4. 不做逐条（per-utterance）CMVN：短句统计不稳定，且 2.7 分钟的全局统计
   已足够代表这批数据的分布。

预期校验：归一化后任一维度的全量 mean≈0、std≈1（单元测试断言）。

## 6. 如何训练（`src/train.py`）

### 6.1 训练配置与理由

| 项 | 取值 | 理由 |
|---|---|---|
| 优化器 | AdamW, lr=1e-3, weight_decay=1e-4 | LSTM+CTC 各层梯度量级差异大，自适应步长友好；解耦权重衰减 |
| 学习率调度 | **无**（恒定 1e-3） | 总步数 ≈ 7 步/epoch × 300 epoch = 2100 步，调度器在此尺度上没有意义；原仓库 StepLR 被覆盖的 bug 从"修好"变成"不存在" |
| warmup | 不做（clip 已兜底） | 早期梯度尖峰由梯度裁剪处理；若实测 loss 爆炸再加 100 步线性 warmup（预留开关） |
| 梯度裁剪 | `clip_grad_norm_(5.0)` | BPTT 长序列防爆的必需项 |
| 精度 | **fp32** | 模型仅 1.9 M、显存占用 <1 GB，AMP 的复杂度与 fp16 下 CTC/log_softmax 数值风险毫无必要（原仓库 AMP 下 CTC 未转 fp32 的坑直接绕开） |
| batch_size | 8（50 条 → 7 步/epoch） | T 最大 555、hidden 128，batch 8 显存远低于 6 GB 上限 |
| 数据加载 | 特征一次性预提取进内存，单进程，无 DataLoader workers | 1.6 万帧 × 80 × 4B ≈ 5 MB，全内存可行；多进程 spawn 开销反而更大 |
| epochs | 300（以曲线为准，配合早停观察） | GPU 上单 epoch < 1 s，总时长分钟级 |
| shuffle | 每 epoch 重排 | 小数据防记忆顺序 |

### 6.2 训练循环（伪代码）

```
feats, targets, feat_lens, tgt_lens = 预提取 + CMVN + 词表编码（全部缓存）
for epoch in 1..300:
    for batch in shuffle(batches_of_8):
        feats_padded, lengths = collate(batch)              # lengths 在 CPU
        log_probs = model(feats_padded, lengths)            # [T,B,29]
        loss = ctc(log_probs, targets_1d, lengths, tgt_lens)  # zero_infinity=True
        optimizer.zero_grad(); loss.backward()
        clip_grad_norm_(model.parameters(), 5.0)
        optimizer.step()
    每 10 epoch:
        在全量 50 条上跑 greedy 解码 → 训练集 CER（监控记忆进度）
        保存 checkpoint（见 §9）
```

### 6.3 预期训练轨迹与诊断

| 阶段 | 现象 | 判断 |
|---|---|---|
| epoch 1–10 | loss 从 ~20–40 缓慢下降或横盘 | 正常（模型先学"输出 blank"） |
| epoch 10–50 | loss 快速下降到个位数 | 学习发生 |
| epoch 50–150 | loss < 1.0，greedy 开始出现完整单词 | 记忆成型 |
| epoch 150–300 | loss 趋近 0，训练集 CER → 0–5% | 收敛，早停保存 |

**失败模式对照**（沿用原规划 §4 排查表，本数据规模下的具体化）：

- loss 恒为 ~ln29≈3.4 不动 → blank 与词表 0 号错位 / encode 索引 +1 遗漏 →
  打印一个 batch 的 `targets` 与 `decode(encode(text))` 人工核对；
- loss 变 inf/nan → `T<2L+1`（已排除）/ 梯度爆炸（查 clip 是否生效）；
- loss 降但解码全空串 → 解码端没去 blank 或归一化不一致 →
  对同一条音频分别在训练/推理路径打印特征 mean/std 对比。

### 6.4 训练验收标准（里程碑 M4）

- loss 单调趋势下降、无 inf/nan；
- 训练集 greedy CER < 10%（目标 < 5%）；
- checkpoint 可被独立脚本加载并复现同样的 CER（自洽性）。

## 7. 如何推理（`src/decode.py`）

### 7.1 Greedy 解码（必做基线）

```
log_probs [T, C]（单条）
  → 每帧 argmax 得到 id 序列 [T]
  → 合并连续相同 id（aa_ _ b → a_b）
  → 删除 blank（a_b → ab）
  → decode: id → 字符
```

`O(T·C)`，无状态、无超参，是 CTC 的精确逐帧决策。
必须与训练走**同一条特征+CMVN+前向代码**（同一模块、同一 checkpoint）。

### 7.2 前缀束搜索（可选增强，v1 不实现）

- 词表只有 29 类、T≤555，纯前缀束搜索的开销在本数据上完全可接受
  （不需要 asr 那种每帧 top-k 剪枝）；
- 实现要点（若做）：维护每条前缀的 `(p_blank, p_nonblank)` 二元组；
  blank 延续 / 同字符延续 / 新字符扩展三个分支；同前缀路径合并；
  beam=5；
- **v1 不做的理由**：greedy 已足够验证链路正确性；beam 只会改善数值、
  不改变"实现是否正确"的结论。作为第二阶段加分项。

### 7.3 批量推理

`eval` 时 batch=8 打包前向（与训练同路径），解码逐条进行。

## 8. 如何评估（`src/eval.py`）

### 8.1 CER 定义

```
CER = (S + D + I) / N
```

- 用 Levenshtein 编辑距离 DP 求 min(S+D+I)，并回溯统计三类错误：
  删除多 → 模型太保守（blank 偏多）；插入多 → 词表/训练有问题；
  替换多 → 声学区分度不够；
- **字符集合**：比较前**从 ref 和 hyp 中同时去掉空格**（英文字符级 CER 的
  惯例，避免空格数偏差主导指标）；撇号参与计数；
- **语料级累加**：`Σ(S+D+I) / ΣN`，绝不对逐条 CER 求平均（短句权重失真）；
- 可选加分：WER（按词比较），同一 DP 换 token 单位即可。

### 8.2 正确性验证

1. 手算样例单元测试：`("abcdef","abcdf")→S=1`；`("abc","abbc")→I=1`；
   `("abcd","abd")→D=1`；空串对全串 → D=N；
2. 与 asr 的 `cer.py` 对同一批 (ref,hyp) 对数，语料级 CER 差值必须为 0；
3. 训练前先做"文本自评"：hyp=ref 时 CER 必须为 0（验证清洗一致性）。

## 9. Checkpoint 与接口契约

```python
checkpoint = {
    "model_state": state_dict,
    "config": {                      # 足够重建模型
        "input_dim": 80, "hidden_dim": 128, "num_layers": 5,
        "num_classes": 29, "dropout": 0.3,
    },
    "vocab_idx2char": [...29 项...], # 纯 JSON 可序列化，不存对象（设计约束第 8 条）
    "cmvn": {"mean": [80], "std": [80]},
    "feature_cfg": {"win":400, "hop":160, "n_fft":512,
                    "n_mels":80, "f_min":80, "f_max":7600},
    "epoch": int, "train_cer": float,
}
```

**契约含义**：任何拿到 `checkpoint + 一条 wav` 的人，不接触训练代码、
不接触 manifest，也能完成"特征→归一化→前向→解码"全流程。
训练/推理/复评三方一致性由此结构保证，而不依赖口头约定。

## 10. 设计约束清单（原 12 坑 → 本项目的规避设计）

| # | asr 的坑 | 本项目设计 |

| 加 | `_simple_mel` 兜底负帧数 | 直接依赖 librosa，不写兜底（§5.1） |
| 加 | 遗忘门偏置 0 初始化 | 改为 1.0（§3.4，设计增强） |
