## 0. 一句话说明我负责什么

把 TIMIT 的原始 `.WAV/.TXT` 语料，加工成模型可以直接读取的一套标准数据：**音频目录 + 文本清单 + 字符词表 + mel 特征缓存 + 全局 CMVN 统计量**，并保证训练集、测试集、推理端使用的数据格式和特征定义完全一致。

数据处理是整条链路的地基。后面三个人（模型搭建、模型推理、准确率测试）都直接调用本部分产出的接口，不再自己读音频、不再自己定义特征。

## 2. 数据从原始语料到模型输入的完整流程

```
TIMIT raw/data/TRAIN/<方言区>/<说话人>/<句子>.WAV + .TXT
        │
        │  prepare_timit.py
        │  ① clean_text：NFKC → 小写 → 只保留 a-z 与词内撇号 → 空格分词
        │  ② select_items：按时长/字符数/CTC 长度约束筛选
        │  ③ soundfile 读取并重写为 16 kHz PCM16 单声道
        ▼
data/proc/audio/<说话人>_<句子>.wav
data/proc/transcription.txt        ← 每行 “xxx.wav 文本”
data/proc/vocab.json               ← blank=0，共 29 类
        │
        │  dataset.py: SpeechDataset
        │  ④ _load_manifest 读清单
        │  ⑤ load_audio_file 读 wav（soundfile，失败回退 wave）
        │  ⑥ extract_mel_spectrogram：25 ms 窗 / 10 ms 帧移 / 80 mel → [T,80]
        │  ⑦ 特征落盘到 cache/mel_<签名>/<utt>.npy
        │  ⑧ compute_global_stats 统计全量 mean/std → cmvn_*.npz
        ▼
__getitem__：特征 + 文本编码 → dict
        │  normalize_features（用全局 CMVN）
        ▼
collate_fn：padding 到 batch 内最大 T
        ▼
features [B, T_max, 80] + labels [B, L_max] + input_lengths + label_lengths
```

## 3. 代码是怎么构建的（逐文件讲解）

### 3.1 `prepare_timit.py`：把 TIMIT 变成标准目录

**（1）全局常量**：`prepare_timit.py` 第 27–32 行

- `SR = 16000`：统一采样率；
- `WIN, HOP = 400, 160`：25 ms 窗、10 ms 帧移，对应 100 帧/秒；
- `MIN_DUR, MAX_DUR = 1.0, 8.0`：时长筛选；
- `MIN_CHARS, MAX_CHARS = 10, 200`：清洗后文本长度筛选；
- `WORD_RE = re.compile(r"[a-z']+")`：只保留小写字母和词内撇号。

**（2）文本清洗**：`prepare_timit.py` 第 35–40 行

```python
text = unicodedata.normalize("NFKC", text).lower()
return " ".join(WORD_RE.findall(text))
```

TIMIT 的 `.TXT` 一行是 `<起始采样点> <结束采样点> 文本`，代码先 `split(None, 2)` 取第三段，再做 NFKC、小写、正则过滤。这样训练清单里的文本和 CER 评估用的参考文本来自同一份数据，不会出现“训练时带标点、评估时去标点”的不一致。

**（3）帧数公式**：`prepare_timit.py` 第 43–44 行

```python
def frames_of(num_samples: int) -> int:
    return max(1, 1 + (num_samples - WIN) // HOP)
```

该公式与 `dataset.py` 的 `_simple_mel` 完全一致，用来在**入库前**校验 CTC 的长度约束 `T >= 2L + 1`。

**（4）语句筛选**：`prepare_timit.py` 第 47–93 行

逐层遍历 `TRAIN/<方言区>/<说话人>/`，对每个 `.TXT`：

1. 默认包含 SA1/SA2 校准句（`include_sa=True`），可用 `--exclude_sa` 排除；
2. 子集模式 `--num > 0` 时每人最多 5 条；
3. 清洗后文本长度必须在 10–200；
4. 音频时长必须在 1.0–8.0 s；
5. `T < 2*L + 1` 的句子直接丢弃（`prepare_timit.py` 第 83–86 行）。

最后一条是 CTC 的硬约束：如果帧数少于“字符数×2+1”，`nn.CTCLoss` 会返回 `inf`。必须在数据阶段过滤，而不是训练时靠 `zero_infinity` 兜底。

**（5）写出音频与清单**：`prepare_timit.py` 第 116–123 行

```python
data, sr = sf.read(str(wav_path))
assert sr == SR and data.ndim == 1
sf.write(str(audio_dir / f"{utt}.wav"), data.astype(np.float32), SR, subtype="PCM_16")
f.write(f"{utt}.wav {text}\n")
```

- `utt = 说话人_句子`，例如 `FCJF0_SI1027`；
- 先断言采样率和单声道，再写 PCM16；
- 清单是**空格分隔**：第一段文件名，其余全部是文本（文本内部也有空格）。下游 `SpeechDataset._load_manifest` 用 `split(maxsplit=1)` 解析，正好匹配。

**（6）词表生成**：`prepare_timit.py` 第 125–148 行

```python
chars = sorted({c for _, _, t, _ in picked for c in t})
idx2char = ["<blank>"] + chars
```

- 从**本批语料实际出现的字符**统计，不注入任何常见字；
- `blank` 固定为索引 0；
- 其余字符排序后依次编号；
- `meta` 中记录来源、条数、说话人数、文本规范化规则、是否含空格、是否含 SA；
- 同时把 `{"idx2char": ...}` 复制到项目根 `vocab.json`，供训练脚本直接加载。

**（7）入口与汇总**：`prepare_timit.py` 第 96–161 行

- 参数：`--src`、`--dst`、`--num`（0=全量）、`--include_sa/--exclude_sa`；
- 结束时打印条数、说话人数、时长 min/max/total/mean、词表类别数、含空格文本比例。

实际用法：

```powershell
python prepare_timit.py --src data\raw\TIMIT\raw\data\TRAIN --dst data\proc
python prepare_timit.py --src data\raw\TIMIT\raw\data\TRAIN --dst data\proc --num 50
```

### 3.2 `dataset.py`：把 wav 变成张量

**（1）log-mel 特征**：`dataset.py` 第 20–51 行（入口）、第 54–77 行（实现）、第 80–99 行（mel 滤波器组）

参数：

| 参数 | 值 | 说明 |
|---|---|---|
| `sample_rate` | 16000 | 16 kHz |
| `n_mels` | 80 | 80 维 mel |
| `n_fft` | 512 | FFT 点数 |
| `hop_length` | 160 | 10 ms 帧移 → 100 帧/秒 |
| `win_length` | 400 | 25 ms 窗 |
| 压缩 | `log10(max(mel, 1e-10))` | 压缩约 60 dB 动态范围 |

实现上用 NumPy 向量化（`sliding_window_view` + `rfft` + 矩阵乘 mel 滤波器组），**不依赖 librosa**。原因写在 `dataset.py` 第 33–36 行：本环境 librosa 首次调用有 numba JIT 开销，多进程预计算时每个 worker 都要编译一次，取数会从毫秒级退化到分钟级。NumPy 路径约 2 ms/条，且训练、缓存、推理三处共用同一函数，避免特征定义漂移。

**（2）音频读取**：`dataset.py` 第 105–142 行

- 优先 `soundfile`，多声道取平均转单声道，采样率不符时重采样；
- `soundfile` 不可用时回退到标准库 `wave` + `struct`，按 16 bit PCM 解包并归一化到 [-1,1]。

**（3）特征缓存**：`dataset.py` 第 148–189 行、第 435–490 行、第 492–519 行

- `CACHE_VERSION = 1`；
- 缓存目录名 `mel_<签名哈希>`，签名包含“采样率 / n_mels / n_fft / hop / win + 提取后端 + 版本”；
- 只要改任一特征参数，签名变化，自动换目录，**不会误读旧特征**；
- `meta.json` 记录签名、条数、预计算耗时；
- `precompute_features()` 全量预计算：任务数 ≥ 64 且进程数 > 1 时用 `ProcessPoolExecutor`，否则串行；只补“缺失或比源音频旧”的条目；
- `_get_features()` 命中缓存时等价于一次 `np.load`，缺失时现算并原子写回（`_save_npy_atomic`，先写临时文件再 `os.replace`，避免多进程写坏文件）。

**（4）全局 CMVN**：`dataset.py` 第 195–212 行、第 521–557 行

```python
mean = concat.mean(axis=0)
std  = concat.std(axis=0) + 1e-8
normalized = (features - mean) / std
```

- 统计对象是**训练集全量**（本数据 1,409,882 帧 × 80 维）；
- 统计结果优先从 `cmvn_*.npz` 读取，缺失才遍历全量重算；
- 缓存文件名带 `mel 签名 + 清单指纹 + 样本数`，换数据/换子集会自动失效；
- 训练、验证、推理**共用这一组** mean/std；推理端从 checkpoint 的 `feature_stats` 读取，不会重新统计。

这是本项目刻意规避的一个坑：原教学代码训练不归一化、推理逐条归一化，输入分布不一致，会导致训练 loss 正常但解码全空。

**（5）字符词表类**：`dataset.py` 第 218–283 行

| 方法 | 行号 | 行为 |
|---|---|---|
| `__init__` | 226–228 | 默认四类：`<blank> <space> <unk> <pad>` |
| `add_text` | 230–235 | 收录文本中出现的新字符 |
| `encode` | 237–254 | 字符 → 索引；**封闭词表没有 `<unk>` 时集外字符直接 `KeyError`** |
| `decode` | 256–267 | 索引 → 文本；默认跳过 blank，把 `<space>` 还原成空格 |
| `save/load` | 272–283 | 只存 `idx2char` 的纯 JSON，不存 Python 对象 |

`encode` 的写法有一个容易踩的坑（`dataset.py` 第 241–244 行注释）：

```python
# 不能写 char2idx.get(c, char2idx[UNK])
# 默认值会被无条件求值，词表没有 <unk> 时即使字符在表内也会 KeyError
```

**（6）数据集类**：`dataset.py` 第 289–588 行

| 方法 | 行号 | 作用 |
|---|---|---|
| `__init__` | 298–352 | 保存特征参数；扫描 `audio/`；读清单；建立缓存路径与签名 |
| `_load_manifest` | 354–382 | 读 `transcription.txt`，用 `split(maxsplit=1)`；无清单时遍历音频并留空文本 |
| `_manifest_fingerprint` | 389–399 | 用“文件名:大小:mtime”的 md5 标识当前清单 |
| `precompute_features` | 435–490 | 批量提特征并落盘 |
| `_get_features` | 492–519 | 读缓存/现算 |
| `compute_global_stats` | 521–557 | 全局 CMVN，带 npz 缓存 |
| `__getitem__` | 562–588 | 取特征 → 截断 20 s → CMVN → 编码文本 → 返回 dict |

`__getitem__` 返回字段（`dataset.py` 第 582–588 行）：

```python
{
  "features": FloatTensor[T, 80],
  "label": LongTensor[L],
  "input_length": T,
  "label_length": L,
  "audio_path": "...wav"
}
```

**（7）变长组批**：`dataset.py` 第 591–622 行

- 取 batch 内最大 `T_max` 和 `L_max`；
- 特征零填充到 `[B, T_max, 80]`，标签零填充到 `[B, L_max]`；
- 同时返回真实长度 `input_lengths`、`label_lengths`；
- 下游模型用 `pack_padded_sequence` 跳过 padding 帧，CTC 用真实长度计算 loss。

**（8）DataLoader**：`dataset.py` 第 625–651 行

- 固定 `collate_fn=collate_fn`、`pin_memory=True`、`drop_last=False`；
- Windows 下默认 `num_workers=0`，原因见 `dataset.py` 第 635–637 行：实测 nw=0 约 65 ms/batch，nw=4 约 244 ms/batch，spawn 与 IPC 开销大于收益。

## 4. 本部分对外提供的“契约”

后三个人只需要记住这 5 条：

1. **目录契约**：`data_dir/audio/*.wav` + `data_dir/transcription.txt`；清单每行 `文件名 文本`，文件名内无空格，文本内可有空格。
2. **词表契约**：`vocab.json` 的 `idx2char` 共 29 项，`blank=0`，空格与撇号占独立槽位，`a–z` 占其余槽位；`encode` 不返回 blank。
3. **特征契约**：`extract_mel_spectrogram()` 输出 `[T, 80]`，`T = 1 + (样本数 - 400)//160`；训练、缓存、推理共用这一份实现。
4. **归一化契约**：全局 CMVN 的 `mean/std` 随 checkpoint 保存为 `feature_stats`；推理端必须用它，不能逐条重新统计。
5. **长度契约**：入模数据已经满足 `T >= 2L + 1`；训练侧仍保留 `zero_infinity=True` 兜底。

## 7. 常见坑与处理

| 现象 | 根因 | 处理 |
|---|---|---|
| 首次提特征极慢（分钟级） | librosa 首次调用 numba JIT，多进程每个 worker 重复编译 | 已改用 NumPy 向量化实现（`dataset.py` 第 54–77 行） |
| 改了特征参数但结果没变 | 缓存目录只按旧签名命中 | 签名包含参数，改参数会自动换目录；必要时 `--rebuild_cache` |
| 训练 loss 正常、解码全空 | 训练/推理归一化不一致 | 全局 CMVN 存 checkpoint，推理读取 `feature_stats`（`dataset.py` 第 521–557 行） |
| `KeyError: 字符不在词表中` | 封闭词表没有 `<unk>`，出现集外字符 | 确认词表来自同一批语料；换数据必须重新生成词表 |
| CTC loss 变 `inf` | 某条 `T < 2L + 1` | 准备阶段已硬过滤；训练仍开 `zero_infinity=True` |
| 文本里的空格被当成多余字符 | 空格是词表第 1 类，参与编码 | 这是设计选择：英文词边界显式建模；CER 阶段可选择去空格 |
| Windows 下 DataLoader 很慢 | `num_workers>0` 的 spawn + IPC 开销 | 默认 `num_workers=0` |
| 子集训练后全量缓存失效 | 缓存按清单指纹区分 | `--limit` 只是取前 N 条，全量缓存仍可复用；CMVN 按清单分开存 |
