# 相对教师原版代码的改进说明

对比对象：
- 原版：`asr/`
- 当前：`asr-my-project/`

结论先行：`model.py` 完全未改（逐字节一致），`inference.py` 只改了 2 处，`cer.py` 只改了 1 处；主要改动集中在 `dataset.py`（+359/−88 行）、`train.py`（+66/−37 行）、`run_demo.py`（重写）、以及新增的 `prepare_timit.py` 和 `data/` 目录。改动的核心不是换模型，而是把原版「跑得起来但学不到东西」的链路修成「能在真实数据上收敛并给出可复现指标」的链路。

---

## 一、总览对比

| 维度 | 原版 `asr/` | 当前 `asr-my-project/` |
|---|---|---|
| 数据来源 | `run_demo.py` 现场合成正弦波，18 条中文句子 | 真实 TIMIT：训练 4618 条 / 462 人 / 236.5 分钟，测试 1680 条 / 168 人 |
| 数据准备 | 无，只有 demo 生成函数 | 新增 `prepare_timit.py`，产出 wav + 清单 + 词表 |
| 词表 | 4 个特殊符 + 约 2500 个常用汉字 | 29 类：`<blank>`、空格、撇号、a–z |
| 词表构建 | 构造后从未 `add_text`，英文全部落入 `<unk>` | 优先加载 `vocab.json`；否则逐条 `add_text` |
| 特征提取 | 优先 librosa（首调有 numba JIT 开销），回退版逐帧 Python 循环 | 统一 NumPy 向量化实现，无 librosa 依赖 |

| 学习率 | warmup 后恒为 base_lr，StepLR 被逐 batch 覆盖 | warmup + 余弦退火到 1% |
| checkpoint | 只有权重、词表、args | 增加 `feature_stats`，推理端直接恢复 |
| 评测产物 | 单个 `eval_result.json` | `evals/` 下测试集、训练集、多个 epoch 的 JSON |
| 实测结果 | 50 条实验曾出现 blank 塌缩，CER 84.47% | 测试集 CER 19.96%，单条真实语音可逐字识别正确 |

## 二、数据层：从「合成正弦波」到「真实 TIMIT」

### 2.1 新增数据准备脚本

原版没有任何数据准备代码，`run_demo.py` 直接用正弦波拼句子：

```python
# asr/run_demo.py 第 40–42 行
for i, char in enumerate(text):
    freq = 200 + (ord(char) % 50) * 20  # 不同字符对应不同频率
    audio += 0.1 * np.sin(2 * np.pi * freq * t * (1 + 0.1 * np.sin(2 * np.pi * 3 * t)))
```

这种做法的问题很直接：音频和文字是人为构造的对应关系，模型学到的不是语音，而是「频率 → 字符」的查表，无法迁移到真实语音。

当前新增 `prepare_timit.py`，负责挑句子、统一采样率、写标准 wav 和清单、统计词表：

```python
# prepare_timit.py 第 116–123 行：写音频与清单
with open(dst / "transcription.txt", "w", encoding="utf-8") as f:
    for utt, wav_path, text, dur in picked:
        data, sr = sf.read(str(wav_path))
        assert sr == SR and data.ndim == 1, f"{utt}: sr={sr}, shape={data.shape}"
        sf.write(str(audio_dir / f"{utt}.wav"), data.astype(np.float32), SR,
                 subtype="PCM_16")
        f.write(f"{utt}.wav {text}\n")
```

```python
# prepare_timit.py 第 125–148 行：词表 = blank + 语料中出现的字符
chars = sorted({c for _, _, t, _ in picked for c in t})
idx2char = ["<blank>"] + chars
```

可核对的数据证据：
- `data/proc/audio` 4618 个 wav，`data/proc/transcription.txt` 4618 行；
- `data/proc_test/audio` 1680 个 wav，对应 168 个说话人；
- `vocab.json` 的 `idx2char` 恰好 29 项。

### 2.2 修复词表构建 bug（这是原版最致命的一处）

原版 `train.py` 构建词表时只实例化了 `SpeechDataset`，从来没有把文本字符加进词表：

```python
# asr/train.py 第 231–243 行
vocab = Vocabulary()
train_dataset = SpeechDataset(args.train_dir, vocab)
vocab.save(args.vocab_path)
print(f"词表大小: {len(vocab)}")

if len(vocab) < 6000:
    common_chars = "的一是在不了有和人这中大为上个国..."  # 2500 个常用汉字
    for char in common_chars:
        vocab.add_text(char)
    vocab.save(args.vocab_path)
```

`Vocabulary()` 初始只有 4 个特殊符，`SpeechDataset` 只加载音频路径和文本、不调用 `add_text`，所以词表里没有 a–z；随后又强行补了 2500 个汉字。结果是英文语料里每个字符在 `encode` 时都落到 `<unk>`，模型只学到一个符号，解码输出必然是乱码或空串。这正是原版 50 条实验里 CER 84.47%、以及「全 blank 塌缩」现象的直接来源之一。

当前的做法：

```python
# train.py 第 250–261 行
if os.path.exists(args.vocab_path):
    vocab = Vocabulary.load(args.vocab_path)
else:
    vocab = Vocabulary()
    for _, text in SpeechDataset(args.train_dir, vocab).samples:
        vocab.add_text(text)
    vocab.save(args.vocab_path)
```

并且 `Vocabulary.encode` 改为显式处理集外字符，避免默认值被无条件求值导致 `KeyError`：

```python
# dataset.py 第 245–253 行
unk_idx = self.char2idx.get(self.UNK)
ids = []
for c in text:
    idx = self.char2idx.get(c)
    if idx is None:
        if unk_idx is None:
            raise KeyError(f"字符 {c!r} 不在词表中，且词表未定义 <unk>")
        idx = unk_idx
```

定性效果：词表从「2500+ 类、实际全部映射到 UNK」变成「29 类、每个字符都有唯一编号」，输出层也随之从 5000 类缩到 29 类。

## 三、特征层：可复现、可缓存、可对齐

### 3.1 特征提取改为纯 NumPy 向量化

原版优先走 librosa：

```python
# asr/dataset.py 第 43–58 行
import librosa
mel_spec = librosa.feature.melspectrogram(...)
log_mel = np.log10(np.maximum(mel_spec, 1e-10))
```

回退实现则是逐帧 Python 循环：

```python
# asr/dataset.py 第 78–82 行
for i in range(num_frames):
    start = i * hop_length
    frame = audio[start:start + win_length] * window
    fft = np.fft.rfft(frame, n=n_fft)
```

当前统一走 NumPy，并用滑窗视图一次算完所有帧：

```python
# dataset.py 第 51 行
return _simple_mel(audio, sample_rate, n_mels, n_fft, hop_length, win_length)

# dataset.py 第 69–71 行
frames = np.lib.stride_tricks.sliding_window_view(audio, win_length)[::hop_length]
frames = frames[:num_frames] * window
spec = np.abs(np.fft.rfft(frames, n=n_fft, axis=1)).astype(np.float32)
```

改进点有两个：一是去掉 librosa 首次调用的 numba 编译开销（代码注释记录该开销可达数分钟）；二是训练、缓存、推理三处共用同一实现，不会出现「训练用 A 版本、推理用 B 版本」的特征漂移。

### 3.2 新增磁盘特征缓存

原版每条样本在 `__getitem__` 里现算：

```python
# asr/dataset.py 第 302–310 行
def __getitem__(self, idx):
    audio = self._load_audio(audio_path)
    features = extract_mel_spectrogram(audio, ...)
```

意味着每跑一个 epoch，4618 条音频就要重算 4618 次。按当前代码注释里记录的「原实现约 0.3 s/条」估算，单是特征提取每 epoch 约 23 分钟，且完全消耗在 CPU 上。

当前把特征一次性落盘，并给缓存目录做参数签名：

```python
# dataset.py 第 338–343 行
self._sig = {**self._mel_params, "backend": _mel_backend(), "version": CACHE_VERSION}
self._sig_hash = hashlib.md5(json.dumps(self._sig, sort_keys=True).encode()).hexdigest()[:10]
cache_root = cache_dir or os.path.join(data_dir, "cache")
self.cache_root = os.path.join(cache_root, f"mel_{self._sig_hash}")
```

取数时只读缓存：

```python
# dataset.py 第 494–500 行
if self._cache_ready:
    path = self._feature_cache_path(idx)
    if not self._cache_stale(idx, path):
        try:
            return np.load(path)
```

配套的工程细节：
- `_save_npy_atomic`（第 156–160 行）先写临时文件再替换，避免多进程写坏；
- `_scan_dir_meta`（第 163–180 行）一次 `os.scandir` 收集 size/mtime，避免 4618 条各做两次 `stat`；
- `precompute_features`（第 435–490 行）只补缺失或过期的条目，支持 `force` 全量重建。

可核对的数据证据：
- `data/proc/cache/mel_25da37945f/` 共 4619 个文件（4618 个 `.npy` + `meta.json`），合计 451,753,631 字节（约 431 MiB）；
- `meta.json` 里签名固定为 `sample_rate 16000 / n_mels 80 / n_fft 512 / hop 160 / win 400 / backend numpy / version 1`；
- `cmvn_*.npz` 共 8 份，对应 8 / 64 / 100 / 192 / 200 / 4618 等不同子集，说明统计量缓存会随样本集自动换名。

### 3.3 归一化从「逐条」改为「全局 CMVN」

原版每条样本用自己的均值方差归一化：

```python
# asr/dataset.py 第 128–132 行
if stats is None:
    mean = features.mean(axis=0, keepdims=True)
    std = features.std(axis=0, keepdims=True) + 1e-8
    stats = {"mean": mean, "std": std}
```

推理端同样如此（`asr/inference.py` 第 80 行），每条测试音频用自身统计量。这会把「说话人音量和信道差异」抹掉一部分，但更严重的问题是：训练时每条样本的分布也被各自拉平，模型学不到统一的输入尺度，推理时又换了另一套统计量，训练/推理输入分布不一致。

当前先在整个训练集上统计一次：

```python
# dataset.py 第 540–545 行
all_feats = [self._get_features(i) for i in range(len(self.samples))]
concat = np.concatenate(all_feats, axis=0)
self.stats = {
    "mean": concat.mean(axis=0).astype(np.float32),
    "std": concat.std(axis=0).astype(np.float32) + 1e-8,
}
```

`__getitem__` 统一用这份统计量（第 574 行），统计量再随 checkpoint 保存：

```python
# train.py 第 352–360 行（best_model 保存片段）
torch.save({
    "epoch": epoch,
    "model_state_dict": model.state_dict(),
    "optimizer_state_dict": optimizer.state_dict(),
    "val_loss": val_loss,
    "vocab": vocab,
    "feature_stats": feature_stats,
    "args": vars(args),
}, save_path)
```

推理端只需加两行就能恢复，这是 `inference.py` 相对原版的全部改动：

```python
# inference.py 第 56–58 行
# 全局 CMVN 统计量（训练时随 checkpoint 保存；旧 checkpoint 缺失则退化为逐条归一化）
self.feature_stats = checkpoint.get("feature_stats")
```

```python
# inference.py 第 82 行
features, _ = normalize_features(features, self.feature_stats)
```

可核对的数据证据：`data/proc/cache/cmvn_25da37945f_8bb9ca59d1_4618.npz` 对应全量训练集，统计时遍历 1,409,882 帧 × 80 维。

## 四、训练层：修掉学习率调度冲突

原版的 `WarmupScheduler` 在 warmup 结束后永远返回 `base_lr`：

```python
# asr/train.py 第 125–134 行
def step(self):
    self.current_step += 1
    if self.current_step <= self.warmup_steps:
        lr = self.base_lr * (self.current_step / self.warmup_steps)
    else:
        lr = self.base_lr
```

同时 `main` 里又建了 StepLR：

```python
# asr/train.py 第 286 行
lr_scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=1, gamma=args.lr_decay)
```

看起来「warmup + 每 epoch 衰减」合理，实际上 `train_epoch` 每个 batch 都调用 `scheduler.step()`，直接把 StepLR 写进 `param_groups` 的学习率再覆盖回 `base_lr`。结果整个训练过程学习率几乎恒定，StepLR 形同虚设，loss 容易在中途横盘。

当前把 warmup 和余弦退火合并成一个调度器：

```python
# train.py 第 140–150 行
if self.current_step <= self.warmup_steps:
    lr = self.base_lr * (self.current_step / self.warmup_steps)
else:
    progress = (self.current_step - self.warmup_steps) / max(
        1, self.total_steps - self.warmup_steps
    )
    lr = self.min_lr + 0.5 * (self.base_lr - self.min_lr) * (
        1 + math.cos(math.pi * progress)
    )
```

`total_steps` 由 epoch 数 × batch 数给出（第 315–320 行），退火下限由 `--min_lr_ratio` 控制（默认 0.01）。

可核对的数据证据（`checkpoints/history.json`）：
- `train_loss` 第 1 项 6.638242 → 最后一项 0.000542870；
- `val_loss` 第 1 项 2.978712 → 最后一项 0.0000419524；
- 100 个 epoch 整体持续下降（中途有小幅波动），没有出现原版那种长期横盘。

另外 `train.py` 还补了两个 CLI 开关，并改了 `num_workers` 的默认值：
- `--no_cache` / `--rebuild_cache`（第 59–60 行），控制特征缓存；
- `--num_workers` 默认从 4 改为 0（第 57–58 行）。

`num_workers` 的理由有实测依据，写在 `create_dataloader` 的注释里：

```python
# dataset.py 第 635–636 行
实测（Windows + 缓存命中）：nw=0 约 65ms/batch，nw=4 约 244ms/batch ——
spawn 启动与 IPC 序列化开销超过收益，故默认 0；Linux 下可适当调大。
```

## 六、效果层面的直接对比

| 指标 | 原版代码可达到的状态 | 当前项目实测 |
|---|---|---|
| 真实语音识别 | 未验证，demo 只有合成正弦 | `FCJF0_SI1027.wav` → `even then if she took one step forward he could catch her`，与标注逐字一致 |
| 训练集 CER | 50 条实验曾 84.47%，并有全 blank 现象 | 0.0032%（4618 条，完全拟合） |
| 测试集 CER | 无测试集流程产物 | 19.96%（1680 条，真实泛化水平） |
| 模型规模 | 输出层默认 5000 类 | 29,982,237 参数（hidden=512，5 层，29 类输出） |
| 单 epoch 特征开销 | 每条现算，按注释约 0.3 s/条 | 缓存命中后只剩 `np.load`，431 MiB 缓存复用 |

一句话总结：原版解决的是「代码结构是否完整」，当前解决的是「数据是否真实、词表是否可用、训练是否收敛、推理是否一致、指标是否可复查」。前者能跑通脚本，后者能拿出可复现的实验结论。

## 七、仍然没有改进的地方（如实列出）

1. **束搜索仍不接语言模型**：`inference.py` 第 161–239 行的 beam search 会退化，实测 `beam=5` 输出 `heven then if she tok one step forward...`，反而不如贪婪解码。
2. **`_prefix_beam_search` 定义了但从未被调用**：`inference.py` 第 244–307 行，属于「写了没接线」。
3. **测试集 CER 19.96% 仍然偏高**：主要错误是替换（10.68%），说明声学模型对易混音的区分不足，需要更大数据或更强模型。
4. **训练集与测试集差距约 6000 倍**：属于过拟合，当前只做了 dropout 和 weight decay，没有做数据增强或早停策略的调参。
5. **`get_intermediate` 仍是简化实现**：`model.py` 第 110–149 行没有真正逐层复制权重，只用于占位分析。
