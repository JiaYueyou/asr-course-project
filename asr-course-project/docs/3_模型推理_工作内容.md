## 0. 一句话说明我负责什么

拿第 2 部分训练好的 checkpoint，把一条 wav 变成一行文字：**加载模型 → 复用训练同款特征与全局 CMVN → 前向得到 `log_probs` → CTC 解码（贪心/束搜索）→ 输出文本与候选分数**。

我的交付物是**可运行的推理接口和真实识别结果**，不是“再写一个模型”。

## 2. 推理数据流

```
checkpoint (.pt)
   │ torch.load
   ▼
vocab + feature_stats + args
   │
wav ──► extract_mel_spectrogram [T,80]
   │       （与训练同一函数）
   ├─► normalize_features(feature_stats)   ← 与训练同一组 mean/std
   ▼
[1, T, 80] ──► model.forward ──► log_probs [1, T, 29]
   │
   ├─ 截断到真实 output_lengths
   ▼
log_probs [T, 29]
   │
   ├─ beam_width == 1 → greedy：逐帧 argmax → 合并重复 → 去 blank → decode
   └─ beam_width > 1  → beam search：维护前缀分数 → 合并 → 取 top-K
   ▼
text + candidates
```

## 3. 代码是怎么构建的（`inference.py`）

### 3.1 `SpeechRecognizer.__init__`：从 checkpoint 恢复一切（第 23–72 行）

```python
checkpoint = torch.load(model_path, map_location=self.device, weights_only=False)
self.vocab = checkpoint["vocab"]
args_dict = checkpoint.get("args", {})
self.feature_stats = checkpoint.get("feature_stats")
self.model = DeepSpeech2(...).to(self.device)
self.model.load_state_dict(checkpoint["model_state_dict"])
self.model.eval()
self.blank_id = 0
```

逐项说明：

| 行号 | 动作 | 意义 |
|---|---|---|
| 54 | `torch.load(..., weights_only=False)` | checkpoint 里有 `Vocabulary` 对象，不能只用 weights |
| 55 | `self.vocab` | 29 类词表，解码时索引 → 字符 |
| 56 | `args_dict` | 重建网络需要 `input_dim/hidden_dim/num_layers/bidirectional` |
| 58 | `self.feature_stats` | 训练集全局 CMVN 的 mean/std，推理必须复用 |
| 60–67 | 重建 `DeepSpeech2` | `num_classes=len(vocab)=29`；`dropout=0.0`（推理关闭） |
| 69–70 | 加载权重 + `eval()` | 切到推理模式，关闭 dropout |
| 72 | `blank_id = 0` | 与词表、CTCLoss 的 blank 对齐 |

> 关键点：`dropout=0.0` 是**重建网络时**就设好的，不依赖 checkpoint 里的 dropout 值；`eval()` 再兜底。

### 3.2 `extract_features`：与训练同源（第 74–86 行）

```python
features = extract_mel_spectrogram(
    audio, self.sample_rate, self.n_mels,
    self.n_fft, self.hop_length, self.win_length)
features, _ = normalize_features(features, self.feature_stats)
features = torch.FloatTensor(features).unsqueeze(0).to(self.device)
```

- **第 76–79 行**：调用 `dataset.py` 的同一个 `extract_mel_spectrogram`，参数与训练一致（16 kHz / 80 mel / 512 FFT / 400 窗 / 160 步）；
- **第 82 行**：用 checkpoint 里的 `feature_stats` 做全局 CMVN；
- **第 57–58 行注释**：旧 checkpoint 若缺少 `feature_stats`，会退化为逐条归一化——这会导致训练/推理分布不一致，是**必须避免**的情况；
- **第 85 行**：补 batch 维，变成 `[1, T, 80]`。

### 3.3 `recognize`：主入口（第 88–124 行）

```python
features = self.extract_features(audio)
input_length = tensor([features.shape[1]])
log_probs, output_lengths = self.model(features, input_length)
log_probs = log_probs[0, :output_lengths[0], :]     # [T, C]
if beam_width == 1:
    return self._greedy_decode(log_probs)
else:
    return self._beam_search_decode(log_probs, beam_width)
```

- **第 111 行**：特征提取；
- **第 112 行**：真实长度（batch=1，就是 T）；
- **第 115 行**：前向，得到 `[1, T, 29]`；
- **第 116 行**：按 `output_lengths` 截断，去掉 padding；
- **第 118–124 行**：`beam_width == 1` 走贪心，否则走束搜索。

### 3.4 贪心解码（第 129–156 行）

```python
_, max_indices = log_probs.max(dim=-1)       # 每帧 argmax
decoded = []
prev_idx = -1
for t, idx in enumerate(indices):
    if idx != blank_id and idx != prev_idx:  # 去 blank + 合并连续重复
        decoded.append(idx)
    prev_idx = idx
text = self.vocab.decode(decoded)
```

三步：

1. **逐帧 argmax**（第 141 行）：每帧取概率最大的类别；
2. **合并连续重复**：`idx != prev_idx` 才追加（第 151 行）；
3. **删除 blank**：`idx != blank_id`（第 151 行），最后 `vocab.decode()` 把索引变回字符（第 155 行）。

这是 CTC 的标准 greedy 解码，`O(T·C)`，无状态、无超参。

### 3.5 束搜索解码（第 161–248 行）

数据结构：`beam = {prefix: (blank_score, non_blank_score)}`，全程对数域。

| 分支 | 行为 |
|---|---|
| 扩展 blank | prefix 不变，`total + log p(blank)` 累加到 blank 分数（两类路径都必须消耗本帧发射概率） |
| 同字符延续 | 两条转移：紧接重复（无 blank）→ prefix 不变，仅非 blank 路径贡献；blank 后重现 → 生成 `prefix + (c,)`，仅 blank 路径贡献 |
| 新字符 | `prefix + (c,)`，blank/非 blank 路径均可转移 |
| 合并同前缀 | 用 `np.logaddexp` 合并多条对齐路径 |
| 裁剪 top-K | 按总分排序，保留 `beam_width` 条；概率 < 3e-7 的字符直接跳过（提速约 2 倍） |

**修复记录（重要，如实说明）**：

- 原实现有两处缺陷：(1) 扩展新字符时把父前缀的 blank 分数**不加发射概率直接携带**，打破概率质量守恒，分数随帧数虚增，重复字符的垃圾前缀胜出（实测子集 CER 60.46% vs 贪心 25.93%）；(2) `a + blank + a` 应生成新前缀 `aa`，原实现把这份概率并回 `a` 自身；
- 已按标准 CTC 前缀束搜索（Hannun et al., 2014）重写，修复后子集 CER 与贪心持平（25.96% vs 25.93%），双字母场景恢复正常；
- 文件里原有的 `_prefix_beam_search` 备用实现同样有缺陷（无法产生双字母），且从未被调用，已删除；
- 无语言模型时束搜索收益 ≈ 0~0.5 点（CTC 条件独立假设下贪心已近似最优），其价值是后续接语言模型时承载 n-best 候选。

### 3.6 批量推理（第 313–332 行）

```python
for audio in audio_list:
    text, _ = recognizer.recognize(audio)
    results.append(text)
```

逐条调用，接口简单；第 4 部分的 `evaluate_model` 也是逐条推理后汇总 CER。

### 3.7 命令行入口（第 338–374 行）

```powershell
python inference.py --model checkpoints\best_model.pt --audio data\proc\audio\FCJF0_SI1027.wav --beam_width 1
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 必填 | checkpoint 路径 |
| `--audio` | 必填 | 单条 wav 路径 |
| `--beam_width` | **10** | 1=贪心；>1=束搜索 |
| `--device` | 自动 | 有 CUDA 用 CUDA |

读取音频在 **第 354–366 行**：`soundfile` 读入、多声道取平均、采样率不符时 `librosa.resample`；识别在 **第 369 行**；打印在 **第 371–374 行**。

> 注意 CLI 默认 `beam_width=10`，直接运行会走束搜索；想要贪心结果请显式写 `--beam_width 1`。

## 5. 推理结果与证据

### 5.1 正式模型贪心解码（完全正确）

```powershell
python inference.py --model checkpoints\best_model.pt --audio data\proc\audio\FCJF0_SI1027.wav --beam_width 1
```

实际输出：

```text
识别结果: even then if she took one step forward he could catch her

候选结果 (Top 1):
  1. even then if she took one step forward he could catch her (score: -7.46)
```

参考文本（`data/proc/transcription.txt` 第 3 行）：

```text
FCJF0_SI1027.wav even then if she took one step forward he could catch her
```

**逐字一致**，说明“checkpoint → 特征 → 全局 CMVN → 前向 → greedy → 解码”整条推理链路是通的。

### 5.2 束搜索对照（修复后与贪心一致）

```powershell
python inference.py --model checkpoints\best_model.pt --audio data\proc\audio\FCJF0_SI1027.wav --beam_width 5
```

实际输出（束搜索修复后）：

```text
识别结果: even then if she took one step forward he could catch her

候选结果 (Top 5):
  1. even then if she took one step forward he could catch her (score: -0.36)
  2. even then if she took one step forwarld he could catch her (score: -4.71)
  3. even then if she took one step forwalrd he could catch her (score: -5.73)
  4. even then if she took one step forward he could catch here (score: -9.08)
  5. even then if she took one step forward he could catch he (score: -9.45)
```

与贪心输出**逐字一致**，且候选有合理梯度：第 2、3 名是 `forward` 的近音变体，第 1 名分数明显领先，说明修复后的打分干净、排序有效。

（历史记录：修复前该命令输出 `heven then if she tok one step forward he could catch her`，且出现 5 条同分候选——那是束搜索两处实现缺陷的表现，已按 3.5 节的修复记录处理。）

**结论**：修复后的束搜索与贪心同口径可用，全量测试集 beam=10 CER 23.17% vs 贪心 23.35%（+0.18 点）。无语言模型时两者基本持平属正常（CTC 条件独立假设），汇报主结果用哪个都行，束搜索的真正价值是后续接语言模型。

### 5.3 轻量演示模型（说明 30 epoch 不够）

```powershell
python inference.py --model demo_checkpoints\demo_model.pt --audio data\proc\audio\FCJF0_SI1027.wav --beam_width 1
```

实际输出：

```text
识别结果: 
候选结果 (Top 1):
  1.  (score: -39.41)
```

`demo_model.pt` 只训练 30 epoch、hidden=128，解码为空串——这是 CTC 训练早期的“blank 主导”状态，不是推理代码错误。用它只做**链路冒烟**，正式演示用 `best_model.pt`。

### 5.4 批量推理证据（由第 4 部分汇总）

- `evals/eval_test.json`：1680 条 TIMIT 官方 TEST，CER **19.96%**；
- 意味着约 **80% 的字符被正确识别**，推理链路在未见说话人上可用；
- 训练集自评 `evals/eval_result.json`：CER **0.0032%**，说明推理代码在“见过的数据”上能几乎完全复现标签。

## 7. 常见坑与处理

| 现象 | 根因 | 处理 |
|---|---|---|
| 解码全空 | `feature_stats` 缺失，退化为逐条归一化；训练/推理分布不一致 | 确认 checkpoint 有 `feature_stats`；不要在推理端重新统计 |
| `ModuleNotFoundError: No module named 'dataset'` | checkpoint 存了 `Vocabulary` 对象 | 在项目根执行，或把项目根加入 `sys.path` |
| 加载后识别结果很差 | 用了 30 epoch 的 `demo_model.pt` | 正式结果用 `best_model.pt`（hidden=512，100 epoch） |
| beam 与 greedy 基本持平 | CTC 条件独立假设下贪心已近似最优；无 LM 时束搜索收益 ≈ 0~0.5 点 | 属正常现象；需要更大收益应接语言模型（浅融合） |
| 采样率不是 16 kHz | wav 采样率与模型输入不一致 | CLI 已自动 `librosa.resample`；批量评估也做了同样处理 |
| 多声道音频 | 模型按单声道训练 | 读入后 `audio.mean(axis=1)` 转单声道（第 357–358 行） |
| 显存不足 | 默认 `beam_width=10` 且句子长 | 用 greedy（beam=1）；或减小音频长度 |
| 输出有大小写/标点 | 词表只含小写字母、空格、撇号 | 这是数据契约；参考文本也做了同样清洗，CER 比较是同口径 |
| 候选分数看起来很奇怪 | beam 的 score 是累计对数概率，不是概率 | 分数只用于排序，不用绝对值解释 |

## 9. 本部分一句话总结（可作汇报收尾）
