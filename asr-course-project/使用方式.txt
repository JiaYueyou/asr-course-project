2. 特征缓存（默认开启，本轮新增）
------------------------------------------------------------
# mel 特征按样本落盘，位置：data\proc\cache\
#   mel_<签名哈希>\<utt>.npy      每条一个（float32，全量约 452 MB）
#   mel_<签名哈希>\meta.json      记录特征参数签名、条数、预计算耗时
#   cmvn_<签名哈希>_<清单指纹>_<条数>.npz   全局 CMVN 的 mean/std
#
# 目录名来自「采样率/n_mels/n_fft/hop_length/win_length + 提取后端 + 缓存版本」
# 的 md5 前 10 位，改了任何一个特征参数都会自动换到新目录，不会误读旧特征。

# 默认行为（无需加参数）：首次缺失才预计算，之后全部命中
python run_demo.py --limit 8

# 关闭缓存（每次都现算特征，仅用于对比 / 排错）
python run_demo.py --no_cache

# 强制重建全部缓存（改了特征实现、或怀疑缓存损坏时）
python run_demo.py --rebuild_cache

# 失效规则：
#   1) 特征参数或 CACHE_VERSION 变化 -> 整体换目录，全部重算；
#   2) 单条音频被重新生成（size/mtime 变化）-> 只重算该条（实测 1/4618）；
#   3) --limit 子集运行不会让全量缓存失效，子集直接复用已有条目。
#
# 清缓存：直接删 data\proc\cache 目录，下次运行自动重建（全量 8 进程约 28s）

4. 正式训练（train.py，支持验证集选优）
------------------------------------------------------------
# 全量训练（推荐：batch_size 32，AMP 默认开启）
python train.py --train_dir data\proc --val_dir data\proc --vocab_path vocab.json --batch_size 32 --epochs 100 --hidden_dim 128 --num_layers 5 --num_workers 0

# 说明：
#   --val_dir data\proc     用同批数据做验证（自评），会保存 best_model.pt
#   不加 --val_dir          只保存 checkpoint_epochN.pt 和 final_model.pt
#   输出目录                checkpoints\（可用 --save_dir 改）
#   --hidden_dim 默认 512   显存允许但更慢；复现实验建议显式写 128
#   --use_amp               默认开启（混合精度），无需手动添加
#
# 学习率：线性 warmup -> 余弦退火到 base_lr * --min_lr_ratio（默认 0.01）
#   total_steps = epochs * len(train_loader)，warmup_steps 默认 1000
#   （旧版 warmup 后 lr 恒定，是 loss 长期横盘的主因，已修复）

7. 常用调优参数速查
------------------------------------------------------------
python run_demo.py --epochs 300            延长训练（CER 仍高时首选）
python run_demo.py --lr 3e-4               降低学习率（loss 横盘时）
python run_demo.py --warmup_steps 200      加长 warmup（早期塌缩时）
python run_demo.py --min_lr_ratio 0.001    退火到更低 lr（后期精修更细）
python run_demo.py --hidden_dim 256        增大模型容量（训练更快记住数据）
python run_demo.py --batch_size 16         加大 batch（显存换速度，6GB 可到 64）
python run_demo.py --num_workers 4         多进程取数（Windows 建议保持 0）
python run_demo.py --show 10               推理演示打印更多样例

诊断口诀：
  loss 卡在 ~3.37(ln29) 且解码全空 -> blank 塌缩：降 lr / 加 warmup / 加 epoch
  CER 高但持续下降                 -> 正常爬坡：加 epoch
  loss=inf/nan                     -> 检查数据长度约束 T>=2L+1
  CER 一直 100%                    -> 词表未收录字符（确认 vocab.json 为 29 类）

8. 硬件与耗时实测（RTX 3060 Laptop 6GB，全量 4618 条）
------------------------------------------------------------
batch_size        8      16     32     64
峰值显存(MB)     234    333    530    926
单 batch(ms)    233.8  199.8  244.0  251.2
每 epoch 计算(s)  135     58     35     18
每 epoch 取数(s)  约 6（缓存命中后，与 batch_size 无关）

结论：6GB 显存完全够用，瓶颈是 GPU 计算而非显存；batch_size 越大吞吐越高。
      建议 32（约 41s/epoch，100 epoch 约 1.1 小时）。
      数据侧 1.27 ms/条，已远低于 GPU 前向反向，不再是瓶颈。

特征缓存实测：
  数据集构造        0.079s（原 2.858s）
  缓存命中检查      0.058s（原 8.53s）
  全局 CMVN         0.008s（首次统计约需遍历一次全量，之后走 .npz）
  全量预计算        28s（8 进程；原 librosa 路径 >20 分钟）
  全量遍历一遍      5.86s（1.27 ms/条）

------------------------------------------------------------
9. 常见问题
------------------------------------------------------------
1) Windows 下 --num_workers 建议 0
   实测 nw=0 约 65ms/batch，nw=4 约 244ms/batch：spawn 启动与 IPC 开销超过收益。

2) 进程最后退出码 -1073740791（0xC0000409）
   出现在打印「演示完成!」之后，是本机 Python 解释器 teardown 的访问违规，
   模型与结果均已正常保存，可忽略。

3) 显存不足（OOM）
   降低 --batch_size（8 起），或减小 --hidden_dim。

4) 运行很久却停在「特征缓存预计算」
   首次运行需生成缓存（全量约 28s）；若提示为全部命中则只有 0.06s。
   怀疑缓存异常时加 --rebuild_cache 重建，或直接删 data\proc\cache。

5) 验证集与训练集同源
   --val_dir data\proc 与 --train_dir 相同，val loss 只反映拟合程度，
   不代表泛化；需要真实泛化指标请另切一份 TEST 划分。
