## 2. 网络结构（`model.py`）

### 2.1 总览

```
输入特征 [B, T, 80]
   │ input_fc: Linear(80→h) + ReLU + Dropout
   ▼ [B, T, h]
pack_padded_sequence（按真实长度打包，跳过 padding）
   │ 5 层双向 LSTM（hidden=h，层间 dropout）
   ▼ [B, T, 2h]
pad_packed_sequence
   │ output_fc: Linear(2h→h) + ReLU + Dropout + Linear(h→29)
   ▼ [B, T, 29]
log_softmax(dim=-1)
   ▼
log_probs [B, T, 29]  → 训练喂 CTCLoss / 推理做解码
```

### 2.2 逐层配置与形状

| 层 | 代码位置 | 配置 | 输出形状 |
|---|---|---|---|
| `input_fc` | `model.py` 第 32–36 行 | `Linear(input_dim, hidden_dim)` + ReLU + Dropout | `[B, T, h]` |
| `lstm` | `model.py` 第 39–46 行 | `num_layers=5`，`batch_first=True`，`bidirectional=True`，`dropout=0.3` | `[B, T, 2h]` |
| `output_fc` | `model.py` 第 51–56 行 | `Linear(2h, h)` + ReLU + Dropout + `Linear(h, num_classes)` | `[B, T, 29]` |
| `log_softmax` | `model.py` 第 103 行 | `dim=-1` | `[B, T, 29]` |

`h = hidden_dim`；正式模型 `h=512`，演示模型 `h=128`。

### 2.3 前向传播（`model.py` 第 68–108 行）

关键步骤：

1. **输入投影**：`x = self.input_fc(x)`（第 83 行）；
2. **变长打包**：`x_lengths` 先移到 CPU（第 86 行），再 `pack_padded_sequence(x, x_lengths, batch_first=True, enforce_sorted=False)`（第 87–89 行）；
   - 为什么必须打包：双向 LSTM 的反向方向从序列末尾开始，padding 帧会污染反向起点；
   - 为什么 `lengths` 在 CPU：PyTorch 的 `pack_padded_sequence` 要求长度张量在 CPU；
   - `enforce_sorted=False`：允许 batch 内长度乱序，不必预先排序。
3. **5 层 BiLSTM**：`packed_output, _ = self.lstm(packed_input)`（第 92 行）；
4. **解包**：`pad_packed_sequence(..., batch_first=True)`（第 95–97 行）；
5. **输出投影 + log_softmax**：第 100–103 行；
6. **输出长度**：`output_lengths = x_lengths`（第 106 行）。LSTM 不改变时间维度，所以输出长度等于输入帧数。

返回值为 `(log_probs, output_lengths)`，`log_probs` 形状 **`[B, T, C]`**。CTC 要求 `[T, B, C]`，转置放在 `train.py` 的 `CTCLossWrapper` 里做（第 105 行），调用方不用关心。

### 2.4 权重初始化（`model.py` 第 60–66 行）

```python
for name, param in self.named_parameters():
    if 'weight' in name and param.dim() >= 2:
        nn.init.xavier_uniform_(param)
    elif 'bias' in name:
        nn.init.constant_(param, 0.0)
```

- 二维及以上权重用 Xavier uniform；
- 所有 bias 初始化为 0。

> 设计文档里写过“遗忘门偏置初始化为 1.0 以加速记忆通路”，但当前代码**尚未单独设置**；这是“设计增强项未落地”，汇报时如实说明即可，不影响主链路。

### 2.5 轻量版 `DeepSpeech2Small`（`model.py` 第 152–219 行）

同样的 5 层结构，但 `bidirectional=False`，输出维度 `h` 而不是 `2h`。用于快速实验；正式结果使用 `DeepSpeech2`。

## 3. 损失函数：CTC（`train.py`）

### 3.1 为什么是 CTC

语音识别输入 T 帧、输出 L 个字符，T ≫ L，且**不知道第几帧对应第几个字符**。CTC 通过“合并连续重复 + 删除 blank”把所有可能的帧级路径边缘化，不需要帧级对齐标注。本数据 T/L 最小 4.12，满足 `T >= 2L + 1`。

### 3.2 `CTCLossWrapper`（`train.py` 第 74–116 行）

```python
class CTCLossWrapper(nn.Module):
    def __init__(self, blank=0, reduction="mean", zero_infinity=True):
        self.ctc_loss = nn.CTCLoss(blank=0, reduction="mean", zero_infinity=True)
```

四个必须处理对的接口细节：

| 细节 | 代码位置 | 说明 |
|---|---|---|
| 输入形状 `[T, B, C]` | `train.py` 第 105 行 | `log_probs.permute(1, 0, 2)`，因为模型输出是 `[B, T, C]` |
| targets 一维拼接 | `train.py` 第 113 行 | `targets[:, :target_lengths.max()]` 截断 padding；`collate_fn` 返回 padded 2D，这里按最大长度截断 |
| `input_lengths` 是真实帧数 | `train.py` 第 108–109 行 | 不是 padded 后的最大 T |
| `zero_infinity=True` | `train.py` 第 84 行 | 个别 batch 若违反长度约束，返回 0 而不是 inf |

`blank=0` 与词表的 `<blank>` 索引一致；`reduction="mean"` 是按 target 长度加权的平均。

### 3.3 训练目标

```
loss = -log P(l | x)
P(l | x) = Σ_{π ∈ B⁻¹(l)} Π_t y_{π_t}^t
```

CTC 的两个性质会影响训练现象：

1. **早期 loss 平坦**：模型先学会“全输出 blank”，loss 会接近 `ln 29 ≈ 3.37`；
2. **尖峰性**：收敛后大部分帧输出 blank，字符被压到少数帧，所以 greedy 输出里出现大量空帧是正常的。

## 4. 训练闭环（`train.py`）

### 4.1 训练入口 `main()`（第 241–393 行）

按执行顺序：

| 步骤 | 行号 | 做什么 |
|---|---|---|
| 1. 加载词表 | 248–263 | 优先读 `vocab.json`；不存在则从训练文本 `add_text` 构建 |
| 2. 加载数据 | 265–281 | `SpeechDataset(train_dir)` / `SpeechDataset(val_dir)`；`precompute_features()`；建 DataLoader |
| 3. 全局 CMVN | 283–287 | `train_dataset.compute_global_stats()`；验证集复用同一组 `stats` |
| 4. 构建模型 | 289–303 | `DeepSpeech2(input_dim=80, hidden_dim, num_layers=5, num_classes=29)`；打印参数量 |
| 5. 损失与优化器 | 305–320 | `CTCLossWrapper(blank=0)`；`AdamW(lr, weight_decay, betas=(0.9,0.999))`；`WarmupScheduler` |
| 6. AMP | 322 | `GradScaler()` |
| 7. 训练循环 | 329–377 | 每个 epoch：`train_epoch` → `validate` → 保存 best/periodic |
| 8. 最终保存 | 379–393 | `final_model.pt` + `history.json` |

### 4.2 学习率调度：warmup + 余弦退火（第 122–153 行）

```python
if step <= warmup_steps:
    lr = base_lr * (step / warmup_steps)
else:
    progress = (step - warmup_steps) / (total_steps - warmup_steps)
    lr = min_lr + 0.5 * (base_lr - min_lr) * (1 + cos(pi * progress))
```

正式训练：`warmup_steps=1000`，`total_steps = 100 × 145 = 14,500`，`base_lr=1e-3`，最低退火到 `1e-5`。

**为什么要有 warmup**：早期梯度尖峰容易把 CTC 直接推进“全 blank”局部最优（blank 塌缩）。先用 1000 步把 lr 从 0 线性拉到 1e-3，再余弦退火，既避免早期塌缩，又能在后期精修。

> 原版 `WarmupScheduler` 在 warmup 结束后恒定返回 `base_lr`，和 `StepLR` 同时使用会每个 batch 覆盖衰减，导致 lr 全程不变、loss 横盘。本版把 warmup 和余弦退火合并成一个调度器（第 122–129 行注释），从设计上消除这个 bug。

### 4.3 单 epoch 训练（第 159–211 行）

```python
optimizer.zero_grad()
with autocast():
    log_probs, output_lengths = model(features, input_lengths)
    loss = ctc_loss_fn(log_probs, labels, output_lengths, label_lengths)
scaler.scale(loss).backward()
scaler.unscale_(optimizer)
clip_grad_norm_(model.parameters(), 5.0)
scaler.step(optimizer); scaler.update()
lr = scheduler.step()
```

- **AMP**：`autocast()` 前向 + `GradScaler` 反向/更新，降低显存、提升吞吐；
- **梯度裁剪**：`clip_grad_norm_(5.0)`，BPTT 长序列防爆；
- **调度器按 step 调用**（第 201 行），不是按 epoch。

### 4.4 验证与 checkpoint（第 214–235 行、第 348–377 行）

- `validate()` 用 `torch.no_grad()`，只算 CTC loss，不参与梯度；
- 验证 loss 创新低时保存 `best_model.pt`（第 349–361 行）；
- 每 `save_interval=5` 个 epoch 保存 `checkpoint_epochN.pt`（第 366–377 行）；
- checkpoint 字段（第 352–360 行 / 第 368–376 行）：

```python
{
  "epoch": ...,
  "model_state_dict": ...,
  "optimizer_state_dict": ...,   # best/periodic 有，final 没有
  "val_loss"/"train_loss": ...,
  "vocab": Vocabulary 对象,
  "feature_stats": {"mean": ..., "std": ...},
  "args": vars(args),
}
```

**checkpoint 契约**：推理端拿到一个 `.pt` + 一条 wav，就能完成“读词表 → 提特征 → 全局 CMVN → 前向 → 解码”，不需要训练代码、不需要重新统计归一化。

> 注意当前实现保存的是 `Vocabulary` **对象**（不是纯 JSON），加载时 `dataset.py` 必须在 `sys.path` 里，否则 `torch.load` 会报 `ModuleNotFoundError: No module named 'dataset'`。这是实现与设计文档 §9 “只存纯 JSON”之间的差异，汇报时可作为“已知待改进项”。

### 4.5 当前实现与设计文档的差异（如实说明）

| 设计文档写的 | 当前代码实际 | 影响 |
|---|---|---|
| 模型返回 `[T, B, C]` | 返回 `[B, T, C]`，在 `CTCLossWrapper` 里转置 | 不影响正确性，调用方需按实际形状理解 |
| 全程 fp32 | AMP 默认开启（`--use_amp` 默认 True） | 速度更快；CTC 在 autocast 下已能稳定训练 |
| 遗忘门偏置初始化为 1.0 | 所有 bias 统一初始化为 0.0 | 收敛稍慢，不影响链路 |
| checkpoint 只存纯 JSON | 存 `Vocabulary` 对象 | 加载需 `dataset.py` 可导入 |
| 推荐 hidden=128 | 正式模型 hidden=512 | 参数量 29.98M，训练更充分 |

## 7. 常见坑与处理

| 现象 | 根因 | 处理 |
|---|---|---|
| loss 长期卡在 ~3.37（ln29），解码全空 | CTC blank 塌缩：早期 lr 太大或 warmup 不足 | 降 lr / 加 warmup / 延长 epoch；正式训练用 1000 步 warmup + 余弦退火 |
| loss 变成 inf/nan | 某条 `T < 2L+1` 或梯度爆炸 | 数据阶段硬过滤 + `zero_infinity=True` + `clip_grad_norm_(5.0)` |
| loss 降但解码全空 | 训练/推理归一化不一致，或解码没去 blank | 检查 `feature_stats` 是否随 checkpoint 保存；检查 `decode` 是否跳过 blank |
| 显存 OOM | batch 太大或 hidden 太大 | 降 batch（32→16→8）或 hidden（512→256→128） |
| 训练速度慢 | DataLoader `num_workers>0` 在 Windows 上 spawn 开销大 | 保持 `num_workers=0`（实测 nw=0 65 ms/batch，nw=4 244 ms/batch） |
| 加载 checkpoint 报 `No module named 'dataset'` | checkpoint 里存了 `Vocabulary` 对象 | 在项目根执行，或把项目根加入 `sys.path` |
| `best_model.pt` 比 `final_model.pt` 大很多 | best 含 optimizer state，final 不含 | 演示/评估用 best，分发权重用 final 或只取 `model_state_dict` |
| 换 hidden 后 checkpoint 加载失败 | `inference.py` 用 `args.hidden_dim` 重建网络；缺 args 时默认 512 | 自定义 checkpoint 必须写入 `args` 中的 `input_dim/hidden_dim/num_layers/bidirectional` |
