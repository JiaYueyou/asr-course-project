### 3:00–4:20 CTC 损失

> 语音识别最难的地方是“对齐”：T 帧输入，L 个字符输出，T 远大于 L，而且不知道第几帧对应第几个字。CTC 的价值就是**不需要帧级对齐标注**。

**【看稿找代码】** 打开 `asr-my-project/train.py`，**第 74–116 行**（`CTCLossWrapper`）：
> “整个 CTC 封装只有 40 行，但四个接口细节必须对。”

**四个细节，逐个指：**

| 细节 | 代码位置 | 现场说法 |
|---|---|---|
| 输入必须是 `[T, B, C]` | `train.py` 第 105 行 | “模型输出 `[B,T,C]`，这里 `permute(1,0,2)` 转成时间优先。” |
| targets 截断 padding | `train.py` 第 113 行 | “`collate_fn` 返回 padded 标签，这里按 `target_lengths.max()` 截断。” |
| 长度是真实帧数 | `train.py` 第 108–109 行 | “传的是 padding 前的真实长度，不是最大 T。” |
| `zero_infinity=True` | `train.py` 第 84 行 | “个别 batch 若违反 `T>=2L+1`，返回 0 而不是 inf，避免污染整个训练。” |

> 还有一个关键约定：`blank=0`，和词表的 `<blank>` 索引一致（第 82–85 行）。

> 训练时有两个现象要认识：
>
> 第一，**早期 loss 会卡在 3.37 左右**，这是 `ln(29)`。模型先学会“全输出 blank”，这是 CTC 损失面上一个宽而稳的局部最优，不是 bug。
>
> 第二，**收敛后大部分帧输出 blank**，字符被压到少数帧，所以 greedy 解码出现大量空帧是正常的，这是 CTC 的尖峰性。
>
> 我们上一版 50 条实验就踩过 blank 塌缩：lr=1e-3 没有 warmup，loss 从 12 降到 2.98 后横盘，解码全空。所以正式训练加了 warmup。

## 五、预判提问与回答

| 可能被问 | 建议回答 |
|---|---|
| 为什么是 5 层，不是 3 层或 7 层？ | 复现主题就是“5 层 BiLSTM + CTC”，层数是算法身份；缩 hidden 只改容量，删层就变成另一个模型。 |
| 为什么双向？ | 离线识别，整句音频一次性输入，未来帧可用；双向能提升声学上下文建模。实时场景才需要改单向。 |
| 为什么用 CTC，不用 attention？ | CTC 不需要帧级对齐，保持“端到端从无对齐文本学习”的主题；attention 在数据量小时容易过拟合，且换了算法本体。 |
| 为什么正式模型 hidden=512，而教程写 128？ | 128 是快速演示配置（`demo_model.pt`，1.89M 参数）；512 是正式训练（29.98M），6 GB 显存足够。 |
| 为什么 loss 一开始是 6.64，不是 3.37？ | 初始模型还没学会“全 blank”，随机输出在 29 类上的负对数似然约在 3.4–6.6 区间；前几个 epoch 先快速学会 blank。 |
| 为什么 val_loss 比 train_loss 低？ | 验证时 dropout 关闭，训练时 dropout 开启；且验证集与训练集同源，val 只反映拟合程度。 |
| warmup 为什么是 1000 步？ | 总步数约 14,500，1000 步约占 7%；足以越过早期不稳定区，又不至于浪费太多训练步。 |
| 为什么用 AMP，CTC 在 fp16 不会出问题吗？ | `autocast` 会让 CTC/softmax 等数值敏感算子走 fp32；`GradScaler` 防止梯度下溢。当前训练稳定，未出现 inf/nan。 |
| 训练一次要多久？ | batch=32 约 41 s/epoch（含取数），100 epoch 约 1.1 小时（RTX 3060 Laptop 6 GB）。 |
| checkpoint 为什么这么大？ | `best_model.pt` 含优化器状态（AdamW 的 m/v），所以约 359 MB；`final_model.pt` 不含优化器，约 119.9 MB。 |
