### 0:40–2:10 CER 定义与代码

> CER 的公式是：

```
CER = (S + D + I) / N
```

> S 是替换，D 是删除，I 是插入，N 是参考文本的总字符数。`S+D+I` 就是参考文本和识别文本的最小编辑距离。

**【看稿找代码】** `cer.py` **第 44–60 行**：
> “这是标准的 Levenshtein DP。`dp[i][j]` 表示参考前 i 个字符和识别前 j 个字符的编辑距离。字符相等就继承左上角；否则取删除、插入、替换三种操作的最小值。”

**【看稿找代码】** `cer.py` **第 62–84 行**：
> “只算总距离还不够，我要知道错误类型，所以从右下角回溯：优先匹配，其次替换，再删除、插入，分别计数 S/D/I。这就是为什么我既能报 CER，也能报‘替换多少、删除多少、插入多少’。”

**【看稿找代码】** `cer.py` **第 158–209 行**（`compute_cer_corpus`）：
> “语料级 CER 用的是 `Σ(S+D+I) / ΣN`，**不是**把每条样本的 CER 求平均。第 198 行就是 `total_distance / total_ref_len`。这样长句权重更大，避免短句把指标带偏。”

> 这里有一个容易误解的点：**端到端评估默认包含空格**。`evaluate_model` 调用 `compute_cer_corpus(refs, hyps)` 时没有传 `remove_space=True`（`cer.py` 第 299 行）；而 `_normalize_text` 会删掉撇号等标点（第 227 行）。所以准确说法是：**空格参与 CER，撇号等标点被规范化删除，ref 和 hyp 同规则。**

### 4:30–5:40 结果分析（汇报的“为什么”）

> 现在回答两个问题：为什么训练集几乎 0，测试集却是 19.96%？错误主要错在哪？

**（1）训练集 0.0032% vs 测试集 19.96%**

| 评估集 | 条数 | CER |
|---|---|---|
| 训练集自评 | 4618 | **0.0032%** |
| TIMIT TEST | 1680 | **19.96%** |

> 差距约 **6000 倍**。这不是评估代码写错，而是三个原因：
>
> 第一，训练集自评用的是模型见过的 4618 条，只来自 462 个说话人；
>
> 第二，TEST 是 168 个**未见说话人**，口音、语速、录音条件都不同；
>
> 第三，模型 29.98M 参数、训练 100 epoch，容量足以“记住”训练集，`val_loss` 降到 4.2e-5 也说明拟合非常充分。

**（2）错误构成**

| 评估集 | 替换 | 删除 | 插入 | 主要问题 |
|---|---|---|---|---|
| 训练集 | 0 | **7（100%）** | 0 | 极少数漏字 |
| TEST | **8,410（53.5%）** | 5,197（33.1%） | 2,114（13.4%） | **替换为主** |

> “TEST 上替换占一半以上，说明模型**听到了音，但分不清是哪个字符/词**；删除占三分之一，说明部分字符被 blank 覆盖；插入占 13%，说明有拖音或噪声段多输出了字符。替换为主，指向声学区分度不足，而不是解码器完全失效。”

**（3）为什么不是 0**

- 字符级 CTC 没有语言模型约束，条件独立假设下学不到词间语言规律；
- 词表只有 29 类，没有大小写和标点；
- 训练数据只有 4618 条、236.5 分钟，对声学建模仍偏少；
- 双向 LSTM 需要整句输入，不是流式场景。

---

### 5:40–7:00 结论与下一步

> 我的结论分三层：

1. **链路正确**：训练集 CER 0.0032%，7 个错误，证明“数据 → 模型 → CTC → 推理 → CER”全部打通；
2. **真实水平**：TEST CER 19.96%，约 **80% 字符正确**；
3. **评估可信**：S/D/I 相加等于总 CER，epoch 50→100 单调改善，和训练 loss 趋势一致。

> 下一步可以做的（按优先级）：
>
> 第一，修复前缀束搜索并接入主入口（`inference.py` 第 244–307 行已实现但未接线）；
>
> 第二，增大数据量或做说话人自适应，当前 4618 条对 168 个未见说话人偏少；
>
> 第三，加语言模型融合或帧拼接降帧率，提升声学区分度；
>
> 第四，用 WER（词级）补充字符级 CER，更贴近实际听感。

## 五、预判提问与回答

| 可能被问 | 建议回答 |
|---|---|
| 19.96% 算好还是不好？ | 对“字符级 CTC、4618 条训练、1680 条未见说话人”的设定，约 80% 字符正确是可接受的基线；但对实际应用仍然偏高，主要瓶颈是数据和声学区分度。 |
| 为什么训练集 CER 只有 0.0032%？ | 训练集自评就是“背题”，模型记住了 4618 条；它证明链路正确，不代表泛化。 |
| 为什么测试集替换最多？ | 替换意味着模型听到了音但选错字符，说明声学区分度不足；删除说明部分字符被 blank 覆盖；插入说明有拖音/噪声。 |
| 空格算进 CER 了吗？ | 端到端评估默认**算**（`evaluate_model` 没有传 `remove_space=True`）；撇号等标点会被 `_normalize_text` 删除，ref/hyp 同规则。 |
| 为什么不用 WER？ | 当前是字符级 CTC，词表也是字符级，CER 更直接；WER 可以后续补充，两者用同一套编辑距离思路。 |
| 为什么逐条 CER 没保存？ | 保存时过滤了 `per_sample_cers`，避免 JSON 过大；需要逐条分析可在 Python 里直接调 `compute_cer_corpus()`。 |
| 为什么 epoch 50→100 只降 1.2 个点？ | 已进入平台区；训练 loss 还在降，但泛化指标受数据量和说话人差异限制。 |
| 评估代码会不会有 bug？ | 三重校验：手算样例（`cer.py single`）、S/D/I 相加等于总 CER、与训练集自评（hyp=ref 时 CER=0）对得上。 |
| 1680 条测试集从哪来？ | TIMIT 官方 TEST 划分，未参与训练，见 `data/proc_test`。 |
| 这个结果能说明项目成功吗？ | 能说明**链路复现成功**：训练集 0.0032% 证明每一环都对；19.96% 是当前数据规模下的真实泛化水平，不是失败。 |
